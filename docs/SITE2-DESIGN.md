# 사이트2 디자인 적용

참고 원본: `사이트2/src/app/(frontend)/PrizmApp.tsx`, `styles.css`.

## 카테고리바 추가 적용

원본 `CategorySidebar`를 참고해 현재 Vite 프론트엔드의 홈·카테고리·검색 화면에 260px 사이드바를 적용했습니다. 대분류 아이콘·연한 선택 배경·회전 화살표, 왼쪽 세로선이 있는 하위 분류와 오른쪽 2열 세부 항목 패널을 옮겼습니다. 원본의 카테고리 데이터는 `frontend/src/categoryNavigationData.ts`, 화면과 스타일은 `CategoryNavigation.tsx`, `categoryNavigation.css`에서 관리합니다. 참고용 `사이트2/` 원본은 변경하지 않았습니다.

대분류 버튼은 펼침/접힘만 수행하고 상품 요청을 만들지 않습니다. `카테고리 상품 보기`, 하위 분류 이름과 세부 항목을 선택할 때 기존 검색으로 이동합니다. 중고 항목은 준비 중으로 유지합니다. 데스크톱은 마우스·키보드 포커스와 화살표 버튼으로 세부 항목을 열며 Escape로 닫습니다. 모바일은 카테고리 버튼 아래에 목록을 펼치고 세부 항목은 내부에 표시합니다. 바깥 클릭·Escape·항목 선택 시 모바일 목록을 닫습니다.

검색 화면의 가로 카테고리 탭은 오른쪽 콘텐츠 위에 유지합니다. 상품 상세에서는 넓은 상세 레이아웃을 유지합니다. 패션·스포츠의 다나와/무신사 선택도 유지하며 무신사에서 세부 항목을 고르면 대응하는 분류와 성별을 함께 전달합니다. 분류 이름은 검색용 탐색 항목이며 실제 API가 그 조건에 해당하는 모든 상품을 제공한다고 보장하지 않습니다.

확인 항목: 홈·검색의 대분류 펼침, 세부 메뉴로 마우스 이동, 키보드 Tab/Escape, 모바일 펼침과 바깥 클릭, 하위 항목 검색, 무신사 패션 분류 연결, 다크 모드. 실행·빌드·테스트·브라우저 확인은 수행하지 않았습니다.

원본은 Next.js/Payload로 작성되어 있으나 디자인은 기존 React/Vite 프론트엔드에 옮겼다. 원본 폴더와 백엔드는 변경하지 않았다. 의존성 추가 없이 기존 SVG 아이콘·스타일 토큰을 사용한다.

## 적용 범위

- 헤더: 가운데 검색창, 우측 아이콘, 추천 검색어 5개, 기존 최근 검색 기록 유지.
- 홈: 원본의 카테고리 순서·라벨·아이콘, 3장 슬라이드 배너, 3열 상품 카드, 하단 신호 안내·카테고리 탐색, 푸터.
- 카테고리/검색: 상단 가로 카테고리 탭, 그라데이션 배너, 관련 키워드, 실제 검색 결과 카드.
- 상품 상세: 사진과 가격 정보를 나란히 배치하고, 큰 화면에서 380px 우측 리포트·저장·Gemini 패널 표시. 작은 화면은 1열로 배치.
- 기존 비로그인 검색, 최저가 하나 표시, 상세 URL 이동, 이미지 보완·보관, 검색 결과 캐시, Firebase 로그인, 관측 저장과 Gemini 설명 유지.
- 홈은 유효한 브라우저 검색 캐시가 있으면 최근 결과를 표시한다. 없으면 빈 상태를 표시하며 자동 유료 조회는 하지 않는다.

원본에 고정된 할인율·점수·예측 신뢰도·분석 건수·실시간 순위는 복사하지 않았다. 가격·상품 데이터는 실제 응답을 사용한다. 추천 검색어는 순위 집계가 아닌 탐색 바로가기다. ‘중고 최저가’, 찜, 커뮤니티는 해당 실제 서비스 연결이 없어 비활성 상태로 표시한다. 구매 판단 보류 규칙은 유지한다.

배너는 원본과 같은 18초 순환이며 마우스를 올리거나 키보드 포커스가 들어가면 정지한다. 움직임 감소 설정에서는 자동 전환을 끈다.

## 사용자가 직접 확인할 순서

1. 실행 중인 Vite를 새로고침한다. 필요하면 `frontend`에서 `npm run dev`로 재시작한다.
2. 홈에서 카테고리와 3장 배너, 최근 비교 상품(유효 캐시가 있을 때), 하단 안내·탐색 영역, 푸터를 확인한다.
3. 카테고리를 눌러 가로 탭과 카테고리 배너가 나타나는지, 관련 키워드 검색이 동작하는지 확인한다.
4. 상품 상세의 사진·가격 요약과 우측 리포트, 목록 복귀/뒤로가기, 이미지 표시를 확인한다.
5. 기존 계정으로 로그인한 뒤 관측 저장·이력 조회·Gemini 설명을 필요할 때 확인한다. 이러한 요청은 실제 서비스 비용이 발생할 수 있다.
6. 모바일 폭, 다크 모드, 키보드 포커스, 움직임 감소 설정을 확인한다.
7. 타입/빌드 검증: `frontend`에서 `npm run build`.

설치·실행·빌드·테스트·브라우저 렌더링·실제 API 호출은 수행하지 않았다. 소스 대조와 정적 확인만 수행했다.

## 로그인·회원가입 화면
사이트2의 `EntryPage(view=profile)`와 `AuthPanel`을 기준으로 로그인 화면도 수정했다.

- 실제 모드의 헤더 사용자 아이콘과 저장 기능의 로그인 유도는 팝업 대신 페이지 본문을 전환한다. 기존 상품/검색 상태는 숨겨서 유지하고 인증 완료 또는 ‘상품 둘러보기’ 시 돌아간다. 헤더·다크 모드·푸터는 유지한다.
- 왼쪽 소개 그라데이션·PRIZM MEMBER·혜택 타일, 오른쪽 폼의 2열 비율/테두리/모서리/여백을 원본에 맞췄다. 모바일은 1열이다.
- 로그인/회원가입 탭, 둥근 입력창과 기본 버튼, 로그인된 계정의 아바타/이름/이메일 카드와 로그아웃 버튼을 적용했다.
- Firebase 이메일 인증은 유지한다. 회원가입 시 2~24자 표시 이름을 Firebase Auth 프로필에 저장한다. 신규 비밀번호는 8자 이상이며 기존 6~7자 계정의 로그인은 계속 허용한다. Firebase 프로젝트에 설정한 실제 암호 정책은 서버가 별도로 적용한다.
- 가입은 성공했지만 이름 저장만 실패하면 계정 생성 사실을 안내하고 중복 가입을 유도하지 않는다.
- 기존 계정 삭제는 계정 관리 펼침 영역에서 제공하며 재인증·삭제 동의·삭제 처리는 유지한다.
- 로그인 처리 중 헤더 탐색과 폼 중복 제출을 막는다. 계정 화면을 열거나 닫는 동작으로 상품 검색 API를 자동 호출하지 않는다.

사용자 확인: 헤더 사용자 아이콘 → 로그인 페이지 확인 → 로그인/회원가입 탭 전환 → 기존 계정 로그인 → 상품 화면 복귀 → 사용자 아이콘에서 계정 카드/로그아웃 확인. 신규 가입이 필요하면 표시 이름과 암호 정책을 확인한다. 모바일·다크 모드·키보드 탐색도 확인한다. 삭제 검증은 실제 삭제 의도가 있는 계정에서만 수행한다.

이 변경도 실행·빌드·테스트·실제 인증 호출은 수행하지 않았다. 프론트엔드를 새로고침하고 필요하면 `frontend`에서 `npm run build`로 확인한다.
