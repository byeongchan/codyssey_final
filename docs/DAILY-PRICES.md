# 더미 관측의 일별 대표 가격 집계

코드와 테스트 소스를 작성했으며 설치·실행·빌드·테스트는 수행하지 않았다. 실제 Reef 수집은 아직 없다. 새 더미 관측은 fixture 파일로 입력하고 API·Node를 같은 파일로 재시작한다. 브라우저가 임의 가격을 전송하는 경로는 추가하지 않았다.

## 집계 규칙

STORE_SNAPSHOT 작업과 기존 내부 스냅샷 저장 API에서 전체 입력을 DataPolicy로 검증한 뒤 상품별로 집계한다. 잘못된 금액·중복 ID·상품 참조·미래 관측은 저장하지 않는다.

- observedAt을 Asia/Seoul 날짜로 변환한다. UTC 15:00부터 한국의 다음 날짜다.
- 재고 있음·KRW·배송비 확인 관측만 유효하다. 확정 비교가는 상품가 + 배송비 - 무조건 할인이다. 조건부 혜택은 차감하지 않는다.
- 같은 상품·날짜의 확정 비교가 최저값을 comparablePrice, 유효 관측 레코드 수를 validSamples로 저장한다. 서로 다른 ID의 동일 가격도 별도 관측이다.
- 원시 관측이 있는 날짜는 기존 일 대표값을 대체한다. 그 날짜의 관측이 전부 품절·배송비 미확인이면 결과에서 제거한다. 0원으로 채우지 않는다.
- 원시 관측이 없는 과거 날짜는 기존 합성 일 이력을 유지한다. 실제 관측을 복원한 값이 아니다. 결측 날짜를 생성하지 않고 최신 90개 날짜만 보관한다.
- 매번 같은 원시 배열에서 다시 계산하며 이전 스냅샷의 표본 수를 더하지 않는다. 새 관측 입력 시 보존할 기존 관측도 파일에 포함해야 한다. 여러 저장 배치의 원시 관측을 자동 병합하는 기능은 아직 없다.

관측 레코드 하나가 판매처의 한 시점 표본이다. 같은 판매처를 여러 시각에 관측하면 서로 다른 ID로 추가한다. 과거 표본도 해당 날짜의 이력 집계에는 사용한다. 현재가·알림의 24시간 만료 검사는 별도로 적용한다. 관측 시각·기준 시각을 서버 실제 시각으로 덮어쓰지 않는다.

## 저장과 조회

새 내용에 dailyPriceAggregationVersion=1을 넣고 내용 해시에 포함한다. 자동 저장 키 접두사는 fixture-snapshot-v2:다. 구버전 영수증을 덮어쓰지 않는다. 직접 지정한 기존 멱등 키를 변경된 내용으로 재사용하면 409이므로 새 키를 사용한다.

집계 버전이 있는 근거는 재계산 결과와 일 대표값이 일치하는지 조회 때 검증한다. Firestore 정수의 Long 변환도 허용한다. 선택 순서는 최신 판매처 관측 시각 → 집계 버전 → 마지막 일 대표값 날짜 → 내용 해시다. 같은 관측 시각의 구버전과 신버전이 공존하면 새 집계 근거를 선택한다. 구버전만 있으면 계속 조회한다.

CATALOG_SOURCE=fixture는 파일의 일 이력을 그대로 조회한다. 집계 결과는 CATALOG_SOURCE=snapshot에서 저장 후 선택되어 차트·평균·분석 입력에 반영된다. 영수증 dailyPriceCount는 집계 후 날짜 수다. 알림은 일 최저가 대신 기존 유효 현재가를 사용한다.

## 사용자 직접 실행·검증

설치와 서버 실행은 README, snapshot 설정은 CATALOG-SOURCE.md를 따른다. API에서 CATALOG_SOURCE=snapshot을 적용하고 재시작한다.

1. 기본 fixture로 소니 ‘스냅샷 저장’을 실행한다. 최신 날짜 2026-10-22 결과는 comparablePrice=384900, validSamples=2다. 배송비 미확인 관측은 제외된다. 과거 날짜 포함 일 대표값은 30개다. Emulator UI의 선택된 스냅샷 content.dailyPrices 또는 가격 이력 응답에서 확인한다.
2. 같은 요청 반복과 새 멱등 키 저장 모두 표본 수 2가 유지되어야 한다.
3. 원본 파일을 별도 백업한다. fixtures/prices.json의 소니 첫 판매처 관측을 복사해 offers 배열에 추가한다. ID는 sony-xm5-black-extra, 상품가 380000, 배송비 0, 무조건 할인 0, 재고 IN_STOCK, observedAt은 2026-10-22T02:59:00Z로 설정한다. 다른 필드는 유지한다. API·Node를 재시작하고 새 에뮬레이터 데이터에서 저장하면 최저가 380000, 표본 3이어야 한다. 관측은 고정 기준 시각을 넘지 않아야 한다.
4. 추가 관측만 2026-10-21T14:59:59Z로 바꾸고 두 서버를 재시작·저장한다. 한국 날짜 21일은 380000/표본 1, 22일은 384900/표본 2여야 한다. 추가 관측을 2026-10-21T15:00:00Z로 바꾸면 22일은 380000/표본 3이다. 같은 최종 관측 시각의 다른 후보가 공존하면 내용 해시로 선택하므로 각 시나리오는 새 에뮬레이터 데이터로 검증한다.
5. 해당 날짜의 모든 판매처를 품절 또는 배송비 null로 바꾸면 날짜 점이 사라져야 한다. 관측이 없는 과거 날짜는 유지되어야 한다. 이 시나리오도 새 에뮬레이터 데이터로 확인한다.
6. 중복 ID·미래 관측·음수 가격은 API 시작 또는 저장 검증이 거부해야 한다. 스냅샷·영수증·알림 이벤트가 생성되면 안 된다.
7. 백업을 복원하고 API·Node를 재시작한다. 실험 스냅샷은 별도로 정리하거나 새 에뮬레이터 데이터로 시작한다. 미래 관측의 보관 데이터가 남으면 기존 조회 검증이 거부할 수 있다.

테스트 소스는 비교가·표본 수·한국 자정·결측·재집계·90개 날짜 제한·구버전 선택 우선순위·Firestore 정수 호환·집계 불일치 거부를 다룬다. 사용자가 직접 실행한다.

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
```

실제 SDK 저장·재선택·차트와 AI 입력 반영은 수동 절차로 별도 확인한다. 테스트 실행 결과는 아직 없다.
