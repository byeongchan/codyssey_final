# 최근 비교 기록과 계정 삭제 (Firebase Emulator)

이 기능은 Firebase Authentication/Firestore 에뮬레이터 전용이다. 상품·가격·AI 응답은 기존 fixture를 사용한다. 실행·빌드·테스트는 수행하지 않았으며 아래 절차는 사용자가 직접 수행한다.

## 최근 기록

- 상품 상세가 정상 표시되면 로그인 사용자만 `POST /api/v1/me/history/{id}`로 기록한다. 비로그인 방문 기록은 전송·이관하지 않는다.
- `users/{verifiedUid}/history/{productId}`에 상품 ID와 서버 방문 시각을 저장한다. 같은 상품은 한 문서만 유지하고 마지막 방문 시각을 갱신한다. 구매나 AI 분석 완료 기록을 뜻하지 않는다.
- `GET /api/v1/me/history?limit=20&cursor=...`는 마지막 방문 시각 내림차순이다. limit는 1~50, 응답 `nextCursor`를 그대로 사용한다. 커서는 시각·문서 ID를 포함하므로 커서 상품을 삭제해도 다음 페이지를 조회할 수 있다. 조회 중 재방문으로 순서가 바뀌면 첫 페이지를 다시 열어 최신 상태를 확인한다.
- `DELETE /api/v1/me/history/{id}`는 해당 기록만 삭제한다. 삭제한 상품을 다시 방문하면 다시 기록한다. 목록에서 상품 정보가 404이면 판매 종료 안내와 기록 삭제를 제공한다.
- 헤더 시계 버튼 또는 `?view=history`에서 목록을 연다. 화면당 20개씩 조회한다. 현재는 자동 보존 기간·최대 저장 개수 제한 없이 상품별 마지막 기록을 보관한다. 실제 서비스 전 보존 정책을 추가해야 한다.

## 계정 삭제

`DELETE /api/v1/me/account`에 `{"confirm":true}`와 본인 ID 토큰을 보낸다. 서버가 검증한 `auth_time`이 최근 5분 이내여야 한다. 토큰 갱신만으로는 재인증이 되지 않는다. 화면은 현재 비밀번호로 Firebase 재인증한 뒤 요청한다. 비밀번호는 Spring API로 전송하지 않는다.

1. `users/{uid}`에 `deletionState=DELETING`을 저장한다. 이 시점부터 취소할 수 없다. 찜 저장, 알림 설정, 기록 저장, 대화 저장, 스케줄러의 알림 생성은 같은 루트 문서를 트랜잭션에서 읽으므로 삭제와 경합해도 새 개인 문서를 만들지 못한다. 삭제 중 읽기에는 아직 정리되지 않은 본인 데이터가 잠시 보일 수 있다.
2. 호출마다 alerts → notifications → wishlist → history → conversations 중 남아 있는 첫 컬렉션에서 최대 100개 문서를 삭제하고 `data.state=DELETING`을 반환한다. 클라이언트는 같은 요청을 반복한다. 화면은 한 번에 최대 100회 요청하고, 더 필요하면 다시 재인증하여 이어서 처리한다.
3. 다섯 컬렉션이 모두 비면 Firebase Auth 계정을 삭제하고 `DELETED`를 반환한다. 화면은 로그아웃한다. 데이터 정리 실패 시 인증 계정은 남으므로 다시 재인증하여 같은 작업을 이어갈 수 있다. 에뮬레이터 데이터를 보존했다면 API 재시작 후에도 삭제 상태를 유지한다.
4. 루트 문서는 `deletionState` 하나만 가진 삭제 표식으로 남긴다. 이메일·상품·알림·시각은 저장하지 않는다. 문서 경로에는 UID가 남으므로 완전한 익명화나 모든 식별자 삭제를 의미하지 않는다. 늦게 완료된 요청이 데이터를 재생성하지 못하도록 표식을 유지한다.

Auth와 Firestore 사이에 분산 트랜잭션은 없다. Auth 삭제 후 최종 응답이 유실되면 재요청이 401일 수 있다. 로그아웃 후 같은 계정으로 로그인 가능한지와 에뮬레이터 UI를 확인한다. Auth 삭제 후 표식 갱신 실패 시 `DELETING` 표식만 남을 수 있으며 개인 데이터 정리와 쓰기 차단은 완료된 상태다. 삭제 요청을 중단하거나 브라우저를 닫으면 인증 삭제 전까지 작업이 대기하며, 로그인 후 내 계정에서 다시 실행해야 한다. 백그라운드 삭제 재시도 작업은 아직 없다.

현재 개인 컬렉션은 모두 하위 컬렉션이 없는 문서다. `AccountDeletion.COLLECTIONS`에 명시한 다섯 컬렉션만 정리한다. 현재 대화는 상품별 문서에 최대 20쌍으로 저장한다. 향후 중첩 메시지 컬렉션을 추가할 때 재귀 정리를 구현하고 목록을 확장해야 한다. fixture 카탈로그는 공용 합성 데이터라 삭제 범위에 포함하지 않는다. 분석 작업·캐시는 UID별 프로세스 메모리이며 보관 기간 만료 또는 API 재시작 시 제거된다. 계정 삭제 후에도 이미 접수한 계산은 끝날 수 있지만 삭제된 계정 토큰으로 조회할 수 없다. 루트의 analysisWindowStart·analysisCount 카운터는 삭제 상태 기록의 덮어쓰기에서 제거하고, 삭제 가드로 다시 쓰지 못하게 한다.

## 직접 실행·검증

README의 Firebase Emulator → FastAPI → Spring Boot → React 순서와 기존 환경 변수를 그대로 사용한다. 새 환경 변수나 의존성 설치는 필요 없다. 변경된 API와 프론트엔드는 다시 시작한다.

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
mvn spring-boot:run
```

별도 터미널:

```powershell
cd D:\github\codyssey_final\frontend
npm run build
npm run dev -- --host 127.0.0.1 --port 5173
```

| 확인 | 절차와 기대 결과 |
| --- | --- |
| 기록 순서·중복 | A로 로그인 → 소니 상세 → 맥북 상세 → 소니 재방문 → 시계 버튼. 소니가 맨 위이며 두 상품만 표시된다. |
| 사용자 분리 | A 로그아웃 → B 로그인 → 기록 확인. A 기록이 보이지 않는다. 비로그인 상품 방문은 개인 기록 API를 호출하지 않는다. |
| 기록 삭제 | 목록에서 기록 삭제 → 새로고침. 제거 상태가 유지된다. 상품 재방문 시 다시 나타난다. |
| 입력·인증 | 기록 API에 무토큰 요청은 401. limit=51은 400. 알 수 없는 상품 기록은 404. query/body에 다른 UID를 넣어도 본인 범위만 접근한다. |
| 재인증·동의 | 삭제 동의 없으면 버튼이 비활성화된다. 잘못된 비밀번호로 삭제되지 않는다. confirm 누락·false·문자열은 400. 오래된 auth_time은 401. |
| 삭제·계정 분리 | A에 찜·알림·통지·기록·대화를 생성하고 삭제한다. 에뮬레이터 UI에서 A의 다섯 하위 컬렉션과 Auth 사용자가 사라지고 루트에는 상태만 남는다. B의 데이터와 계정은 유지된다. A는 재로그인할 수 없다. |
| 중단·이어하기 | 별도 개발용 계정에서 API로 삭제 한 번만 호출하여 DELETING 확인 → API 재시작 → 다시 재인증 후 삭제 실행. 남은 데이터 정리 후 DELETED. 중간에 찜/기록 저장·알림 설정은 409이며 스케줄러가 통지를 재생성하지 않는다. |
| 자동 테스트 | mvn test에 개인 API 인증·소유자·확인 입력·삭제 단계, 최근 인증 시각, 삭제 중 쓰기 차단, Auth 삭제 순서 및 OpenAPI 계약 검증이 포함된다. 실제 Firebase 연동·경합은 위 수동 검증으로 확인한다. |

에뮬레이터 내보내기 파일의 과거 복사본까지 제거하는 기능은 아니다. 기존 로컬 백업에는 삭제 전 데이터가 남을 수 있다.
