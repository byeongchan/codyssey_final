# 로컬 운영 상태 화면

구현·테스트 소스·명세를 작성했다. 설치·실행·빌드·테스트는 수행하지 않았다. 기존 목업의 색상·카드·다크 모드·반응형 스타일을 사용한다. 화면 하단의 ‘로컬 운영 상태’ 또는 `http://127.0.0.1:5173/?view=operations`로 진입한다.

## 접근 설정

Firebase Emulator에서 운영용 테스트 계정을 가입하고 Emulator UI Authentication 탭에서 UID를 확인한다. 이메일이 아닌 UID를 API 터미널의 OPERATIONS_UIDS에 지정한다. 여러 계정은 쉼표로 구분한다. 값이 비어 있으면 모두 거부한다. API를 재시작해야 반영된다.

```powershell
cd D:\github\codyssey_final\backend\api
$env:OPERATIONS_UIDS = '운영계정의-실제-UID'
mvn spring-boot:run
```

기존 FIREBASE_MODE, FIREBASE_PROJECT_ID, FIREBASE_AUTH_EMULATOR_HOST, FIRESTORE_EMULATOR_HOST와 다른 서비스 환경 변수는 README/FIREBASE.md대로 설정한다. Spring은 .env를 자동으로 읽지 않는다. frontend에는 UID 허용 목록이나 INTERNAL_API_KEY를 추가하지 않는다. 브라우저는 기존 로그인 토큰으로 같은 출처의 `/api/v1/me/operations`를 호출한다.

이 화면의 링크 자체는 모든 방문자에게 보인다. 로그인하지 않으면 로그인 안내를, 허용되지 않은 계정이면 권한 오류를 표시한다. 실제 권한 검사는 서버에서 검증한 토큰의 UID로 수행한다. 읽기 전용 로컬 운영 기능이며 운영 배포용 역할 관리·감사 시스템은 아직 없다.

## 표시 범위

| 항목 | 의미와 제한 |
| --- | --- |
| 수집 작업 | 현재 API 프로세스에 남은 상태별 건수. 완료/실패 후 1시간 보관, 성공 결과는 5분 후 재사용 만료. 재시작 시 초기화. 검색어·작업 목록·개별 사용자 정보는 노출하지 않음 |
| 마지막 종료 | 가장 최근 종료한 작업의 시각과 해당 작업의 오류 코드. 마지막 실패 전체 이력을 의미하지 않음 |
| 가격 조회 근거 | 현재 파일/snapshot 모드, 선택된 상품 수, 근거 없는 상품 수, 뷰 불러오기 시각과 마지막 갱신 오류. 조회만 하며 재선택을 실행하지 않음 |
| 저장 통계 | 스냅샷·영수증·알림 이벤트 각 최대 500개 문서 표본. 내용 대신 필요한 메타데이터만 조회 |
| 이벤트 상태 | PENDING·PROCESSING·RETRYING·DONE·UNKNOWN별 표본 건수. 실제 개인 알림 생성 건수나 누적 처리량이 아님 |
| 미완료 생성 시각 | 조회 표본에서 DONE이 아닌 이벤트의 가장 오래된 createdAt. 타임스탬프가 없으면 포함하지 않음. 정확한 지연 시간·임대 만료 시각은 아님 |
| 처리 설정 | 저장 완료 평가·주기적 알림 점검 설정. 활성 설정은 정상 동작 보장이 아니므로 상태 변화와 로그를 함께 확인 |

한 컬렉션이 500개를 넘으면 truncated=true와 ‘일부 표본’을 표시한다. 문서 ID 순으로 읽은 일부이며 최근 500개가 아니다. 그때 상태별 건수와 가장 오래된 미완료 생성 시각도 전체 통계가 아니다. 날짜·개수는 스냅샷 생성일·서버 상태이며 고정 fixture 관측 시각과 구분한다.

저장 통계는 같은 Firestore 읽기 트랜잭션에서 가져온다. 수집 메모리·가격 뷰·설정은 각각 조회한 상태이므로 응답 전체가 하나의 전역 시점을 보장하지 않는다. 서비스 간 health 요청, 실제 Reef·Gemini 호출, 비용·성공률·장기 추세 측정은 하지 않는다.

Firestore 조회 실패는 HTTP 200 안의 storage.state=UNAVAILABLE로 표시하고, 수집·가격 뷰·설정은 함께 보여준다. 0건 또는 정상이라고 표시하지 않는다. 로그인 검증 자체가 불가능하면 401/503으로 전체 요청이 실패할 수 있다. 서버 예외 원문·이메일·내부 키·검색어·이벤트 커서는 반환하지 않는다.

자동 폴링은 없다. 진입 또는 ‘상태 다시 확인’에서 조회하며 이동·계정 변경 시 요청을 취소한다. 삭제·재시도·워커 시작 버튼은 제공하지 않는다. 정리는 SNAPSHOT-RETENTION.md의 별도 내부 API 절차를 따른다.

## 사용자 직접 검증

1. 기존 에뮬레이터·API·Node 수집기·프론트엔드를 README대로 실행한다. OPERATIONS_UIDS를 지정한 계정으로 로그인하고 화면 하단 링크를 연다. URL 직접 진입·새로고침·뒤로 가기도 확인한다.
2. 로그아웃 또는 다른 계정 전환 후 이전 계정의 운영 정보가 남지 않아야 한다. 미로그인 API 요청은 401, 일반 계정 토큰은 403이어야 한다. 허용 목록을 비우고 API 재시작 후 운영 계정도 403인지 확인한다.
3. 검색 화면에서 정상 재확인, 장애, 요청 한도 시나리오를 각각 실행한다. 운영 화면에서 다시 확인하여 완료·실패 상태와 마지막 종료 오류 코드를 확인한다. 작업이 빠르면 대기/진행 중 상태는 보이지 않을 수 있다.
4. snapshot 모드로 저장 후 워커 진행에 따라 이벤트가 DONE으로 바뀌는지 수동 갱신한다. 저장 통계와 가격 선택 상품 수를 확인한다. 동일 멱등 요청은 이벤트를 추가하지 않아야 한다. 실제 개인 알림 수는 본인 알림함에서 별도로 확인한다.
5. Firestore만 중단하고 Auth는 유지한다. 조회가 가능하면 저장소 ‘확인 불가’와 나머지 상태가 표시되어야 한다. 연결 복구 후 다시 확인한다. 전체 에뮬레이터 중단으로 로그인 검증도 실패하면 전체 오류가 정상이다.
6. 500개 초과 검증용 기록에서는 일부 표본임이 표시되어야 한다. 가격 content를 운영 응답에 포함하면 안 된다. 네트워크 요청에 X-Internal-Key, 이메일, UID 허용 목록, 검색어가 없는지도 확인한다. Authorization에는 로그인 토큰만 전달한다.
7. 모바일·다크 모드·키보드 조작, 조회 중 화면 이동·계정 전환, 오류 후 재조회 상태를 확인한다. API 재시작 후 수집 기록은 0개가 될 수 있으나 에뮬레이터의 저장 통계는 유지되어야 한다.

작성한 서버 테스트는 UID 기본 거부·미인증/타 계정 거부·부분 장애와 예외 비노출·설정 표시·500개 제한·메타데이터만 조회·수집 상태 만료와 검색어 비노출을 다룬다. 실제 SDK와 화면은 위 절차로 확인한다.

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
```

```powershell
cd D:\github\codyssey_final\frontend
npm run build
```

실행 결과는 아직 없다.
