# 중고 최저가 통합 검색

`중고최저가_구성화면` 폴더의 배너·플랫폼 선택·가로형 상품 카드·우측 가격 요약 디자인을 현재 React/Vite 화면에 적용했습니다. 참고 Next.js 폴더는 수정하지 않았습니다.

## 설정

`backend/collector/.env`에 다음 항목을 추가합니다. 기존 Reef 키와 내부 인증 키를 사용합니다.

```dotenv
REEF_USED_ENABLED=true
```

`DATA_PROVIDER=reef-danawa`는 그대로 유지합니다. Spring API와 Node 수집기를 재시작하고 프론트엔드를 새로고침합니다. 새 의존성이나 Firestore 인덱스 배포는 필요하지 않습니다. 예시 환경 파일에는 유료 조회 활성화를 직접 선택할 수 있도록 `false`로 추가했습니다.

## 사용

1. 좌측 **중고 최저가 → 카테고리 상품 보기** 또는 하위 상품을 선택합니다.
2. 플랫폼을 선택합니다. 중고나라·당근 모두 선택하면 같은 검색어로 두 곳을 함께 조회합니다.
3. **지역 선택** 또는 현재 지역 버튼을 누르면 **지역 변경** 모달이 열립니다. 입력 전에는 인기 동네·주변 지역을 표시하며, 후보가 없으면 불러올 수 있습니다. 첫 진입은 인기 동네, 선택한 동네가 있으면 해당 동네 주변을 필요 시 조회합니다. 입력창 안내는 **지역명을 입력해 주세요**로 표시합니다. 입력하면 저장된 지역 목록에서 전체 주소 검색 결과를 좁혀 보여줍니다. 결과가 많으면 50개까지 표시하고 추가 입력을 안내합니다. 마우스·방향키/Enter로 동네를 선택하면 별도 확인 버튼 없이 적용하고 모달이 닫힙니다. 닫기·Escape·배경 클릭으로 취소하면 기존 지역을 유지합니다. 배경 스크롤과 포커스는 모달 동안 제한하고 닫으면 지역 버튼으로 돌아갑니다. 지역 ID는 내부에서만 처리합니다.
4. **통합 검색**을 누릅니다. 입력·플랫폼 변경만으로는 매물 조회가 발생하지 않습니다. 좌측 카테고리는 검색어를 채우며 자동으로 유료 검색하지 않습니다. 상단 공통 검색창도 중고 화면의 검색어를 채웁니다.
5. 먼저 완료된 플랫폼 결과부터 표시됩니다. 일부 실패 시 성공 결과는 유지하며 해당 플랫폼만 재시도할 수 있습니다. 전체/플랫폼별 결과 보기와 정렬은 추가 호출 없이 동작합니다.
6. 사진·제목·매물 확인 버튼을 누르면 상세를 조회합니다. 원본 플랫폼 이동·찜·최근 본 상품을 지원합니다. 거래는 원본 플랫폼에서 진행합니다.

당근 전용 상품 분류와 판매 중 조건은 당근에만 적용합니다. 중고나라의 거래 상태 코드는 문서에서 의미가 확인되지 않았으므로 임의로 판매 중/완료로 추정하지 않습니다. 미제공 값은 미확인으로 표시합니다. 성별·색상·사이즈 등의 상세 필터는 추가하지 않았습니다.

**가격 범위**에서 최저가·최고가를 입력하고 **가격 적용**을 누르면 두 플랫폼에서 이미 조회한 매물을 같은 범위로 필터링합니다. 한쪽만 입력할 수 있으며, 0~100,000,000원의 정수를 허용합니다. 최저가가 최고가보다 크면 적용하지 않습니다. 입력 범위의 양 끝값도 포함합니다. 가격 조건이 있으면 가격 미확인 매물은 제외합니다. 0원 나눔은 범위에 맞으면 표시하지만 가격 요약에서는 제외합니다. 결과 개수·플랫폼별 개수·가격 요약도 함께 바뀌며 추가 API 호출은 없습니다. 새 검색·추가 페이지·갱신에도 적용한 범위를 유지하고, **초기화**는 가격 조건만 해제합니다.

## 범위와 비용

- 중고나라 검색은 `search`, 상세는 `listing_detail`을 사용합니다. 페이지당 원본 50개를 요청하고, 원본 페이지는 1~2만 지원합니다. **추가 매물 불러오기**로 두 번째 페이지를 읽습니다.
- 당근 검색은 `region_id`가 필수입니다. 동네 주변 매물이 포함될 수 있으므로 실제 매물 지역을 표시합니다. 원본 추가 페이지는 없습니다. 화면의 이전/다음은 이미 받은 매물을 12개씩 나누는 기능입니다.
- 당근 인덱스 대신 동네 피드로 검색한 응답이면 목록 위에 검색 범위 안내를 표시합니다. 결과 크기는 최대 400개 및 정규화된 목록 약 600KB로 제한하고 생략 여부를 표시합니다.
- 중고나라·당근 검색은 각 3크레딧입니다. 두 공급자의 캐시 없는 첫 검색은 합계 6크레딧이며, 동네·카테고리 조회는 각 1크레딧입니다. 상세는 중고나라 3·당근 1크레딧입니다. UI가 모든 카드를 자동으로 상세 조회하지 않습니다.
- 지역명 자동완성은 수집한 정적 JSON을 브라우저에서 한 번 읽어 메모리에 보관하고 입력할 때마다 로컬에서 좁힙니다. 타이핑 중에는 Reef·당근 웹 API·Firestore 조회가 발생하지 않습니다. 수집되지 않은 동네는 자동완성에서 찾을 수 없으며, 원본 검색의 응답 상한 때문에 전국 동네가 완전히 포함된다고 보장하지 않습니다. 인기·인접 동네 조회는 별도 기능으로 유지합니다.
- 기본 검색은 저장된 결과를 재사용합니다. 오래된 데이터도 자동으로 유료 갱신하지 않고 조회 시각을 표시하며, **매물 갱신** 아이콘으로 명시적으로 갱신합니다. 동일 요청은 수집기에서 1분간 재사용하고 공유 작업도 병합합니다.
- 가격 요약은 현재 플랫폼 필터로 표시한 결과에서 최저·평균·최고를 계산합니다. 나눔·가격 미상·예약·판매 완료는 요약에서 제외합니다. 상태 미확인 매물은 포함될 수 있습니다. 서로 다른 상품·모델·구성품·상태가 섞일 수 있어 전체 시장 시세나 동일 모델 최저가를 보장하지 않습니다.
- 참고 화면의 번개장터·N플리마켓, 임의 공급자 치환, 가짜 할인율, AI 급매 분석·알림은 넣지 않았습니다. `급매·최저가` 하위 항목은 검색어로만 사용하며 실제 시세 판단·가격 인하 탐지·등록일 필터가 아닙니다.

## 지역 목록 수집

프로젝트 루트의 `collect-daangn-regions.cjs`를 사용합니다. 기본 참조 파일은 제공된 중고 화면의 `UsedLowestPage.tsx`이며, 현재 폴더 구조에서 찾도록 경로를 수정했습니다. 다른 위치에서 실행해도 결과는 프로젝트 안에 저장합니다.

```powershell
node .\collect-daangn-regions.cjs
```

이 명령은 당근 공개 지역명 경로를 여러 차례 조회하므로 사용자가 직접 실행합니다. Reef 키는 사용하지 않습니다. 403·429 응답이면 중단하고, 주기적으로 결과를 저장합니다. 새 의존성은 필요하지 않습니다.

출력:

- `region-data/daangn-regions.json`: 원본 지역 레코드
- `region-data/daangn-regions.csv`: 원본 확인용 CSV
- `region-data/collection-report.json`: 수집 오류·응답 상한에 걸린 구 목록·수집 시각
- `frontend/public/data/daangn-regions.json`: 자동완성용 동 단위 ID·전체 주소 목록

기존 수집 기록이 있으면 성공한 쿼리는 재사용하고 실패/미완료 쿼리를 이어서 조회합니다. 처음부터 새로 수집하려면 `node .\collect-daangn-regions.cjs --fresh`를 사용합니다. 참조 TSX 위치가 다르면 파일 경로를 인자로 전달할 수 있습니다.

현재는 제공된 `당근 마켓 리전 코드/당근 마켓 리전 코드/region-data` 폴더의 `collection-report.json`과 `daangn-regions.json`을 대조해 동 단위 6,545개를 공개 JSON에 반영했습니다. 보고서의 총 개수·시도별 개수와 원본이 일치하며 오류 0건·응답 상한 기록 27건도 메타데이터에 보존했습니다. 대전 215개 동네가 포함되어 있습니다. 원본 이름·ID는 유지하고 화면용 전체 주소만 조합합니다. 추가 수집 없이 페이지를 새로고침하면 사용할 수 있습니다. 배포 시 공개 JSON이 빌드에 함께 포함됩니다. 원본 데이터는 공식 행정구역 전수 자료가 아니며 누락이 없다고 보장하지 않습니다. 업데이트된 수집본을 다시 반영하려면 `./scripts/import-daangn-regions.ps1`를 사용합니다. 이 스크립트는 로컬 파일만 읽고 외부 API를 호출하지 않습니다.

## 검색 지역 적용과 검색창 배치

선택한 동네 ID는 프론트엔드의 `regionId`, Spring 요청 검증과 지역별 캐시 키를 거쳐 수집기에서 Reef의 `region_id`로 전달합니다. 지역 선택만 바꿨을 때 이전 매물이 남던 동작을 수정했습니다. 이미 당근 검색을 한 상태에서 다른 지역을 고르면 제출했던 검색어로 당근 결과만 다시 조회하며 이전 지역 결과를 비웁니다. 중고나라 결과는 유지합니다. 최초 지역 선택 후에는 통합 검색을 눌러 검색합니다. 결과 상태에 실제 요청 기준 지역명을 표시하며 갱신·재시도도 변경된 지역을 사용합니다.

통합 검색창과 추천 검색어는 검색 플랫폼 카드 안의 지역 조건 아래에 배치했습니다. 실행·테스트·실제 API 응답 검증은 사용자 수행입니다.
## 당근 검색 기준 지역 검증

공식 API 문서의 `region_name`은 매물 자체의 동네이며, 당근은 검색 기준 지역에 결과를 가두지 않고 거리 기준으로 순위를 정합니다. 따라서 관저동을 선택해도 다른 지역 매물이 포함될 수 있습니다. 수집 목록에서 관저동은 `5789`, 관저1동은 `1147`, 관저2동은 `1148`입니다. 이 ID를 그대로 `region_id`에 전달합니다.

수집기는 검색 응답의 `region.region_id`가 요청과 일치하는지 확인하고 없거나 다르면 응답을 거부합니다. 검증한 ID와 실제 응답 지역명을 API와 화면에 전달하며, Spring과 화면에서도 ID를 대조합니다. 매물 자체의 지역명은 원본 그대로 표시합니다. 검증 전 저장된 당근 검색 캐시를 재사용하지 않도록 해당 검색의 캐시 버전을 변경했습니다. 반영하려면 수집기·API를 재시작해야 합니다. 기존 캐시 문서를 삭제하지는 않습니다.

검색 버튼 명칭은 `검색`으로 바꾸고 테두리·입력 영역·포커스 강조가 있는 검색창으로 정리했습니다. 지역 일치·불일치·지역 미제공·타 지역 매물 포함에 대한 목 테스트를 추가했으나 사용자 요청에 따라 실행하지 않았고 실제 상품 API도 호출하지 않았습니다.

근거: https://reefapi.com/docs/karrot.md (`search`의 `region_id`, `region_name`, `region` 반환 설명)
## 지역 ID의 기준 파일

동네 검색뿐 아니라 인기·주변 동네 선택도 원본 `당근 마켓 리전 코드/당근 마켓 리전 코드/region-data/daangn-regions.json`에서 가져온 공개 목록을 기준으로 합니다. 선택 후보의 전체 주소를 목록과 대조하여 JSON의 ID를 사용합니다. API 후보의 ID가 달라도 전체 주소가 유일하게 일치하면 JSON의 ID를 채택하고, 주소를 확인할 수 없으면 동네 검색으로 다시 선택하도록 안내합니다. 동 이름만으로 ID를 추측하지 않습니다. 검색 직전에도 JSON 주소와 ID를 재검사합니다.

원본과 공개 목록의 ID·주소를 대조했으며 불일치는 없었습니다. 관저동의 JSON ID는 `5789`입니다. 실행·빌드·테스트·상품 API 호출은 수행하지 않았습니다.
## 검색·갱신 보완

일반 중고 검색은 저장 시각 기준 1일이 지난 결과를 재수집합니다. 저장 자료가 있어도 새 수집이 진행 중이면 화면은 완료를 기다리고, 실패하면 성공한 검색처럼 처리하지 않습니다. 명시적 갱신의 최소 60초 간격 제한은 유지합니다. 갱신 실패 후 첫 페이지 재시도는 `refresh=true`로 재요청하며, 추가 페이지 조회는 일반 조회를 유지합니다.

검색 버튼과 매물 갱신은 현재 입력한 검색어·선택 플랫폼·동네·판매 중·분류 조건을 사용합니다. 검색 후 동네를 선택하면 현재 조건 전체로 다시 검색합니다. 조건이 달라지면 기존 결과를 비워 서로 다른 조건의 매물이 섞이지 않게 합니다. 재시도와 추가 페이지는 실패하거나 조회 중이던 검색의 조건을 유지합니다. 가격 범위는 기존처럼 화면 필터입니다.

만료된 검색과 유효한 검색의 캐시 처리를 확인하는 목 테스트를 추가했습니다. 실행·빌드·테스트와 실제 API 호출은 수행하지 않았습니다.
