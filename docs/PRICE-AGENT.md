> v12: 실제 질문·최근 대화를 전달하는 상품 상담 챗봇으로 변경했습니다. 카테고리 미지정 시 자동 분류를 보조하고, 개인화된 답변은 공유 Firestore 캐시에 저장하지 않습니다. [최신 구현·설정·검증 안내](NEWS-PRICE-IMPACT.md)가 아래 이전 버전의 질문/공유 캐시 설명보다 우선합니다.

> v10 뉴스 검색은 상품명 대신 관련 카테고리명을 사용합니다. 화면에 검색 카테고리를 표시하고, AI는 기사를 시장 배경 정보로 참고합니다. 선택 상품에 할인이 적용된다고 추정하지 않습니다.

> v8 뉴스 근거 표시: 성공한 검색에 관련 기사가 없으면 ‘최근 관련 뉴스 없음’을 표시합니다. 기사가 있으면 제목·검색 요약과 링크를 보여주고 AI도 해당 기사를 참고합니다. 실패/미설정/미조회는 없음과 구분합니다.

> 뉴스 공급자 v6: 기본은 네이버 뉴스 검색 API입니다. [설정·검색 범위·실행 안내](NAVER-NEWS.md)를 따르세요. RSS는 NEWS_PROVIDER=rss일 때만 사용합니다.

> 표시 정책 v5: 확인된 가격 지표·기간 표본·관련 기사·기준 시각만 표시합니다. 값이 없는 행과 빈 섹션, 뉴스 미설정/누락 안내는 구매 답변에서 생략합니다. 내부 data_limitations와 서버 판단은 유지하며 기간 가격과 현재 결제가의 구분은 짧게 안내합니다.

> 현행 v4: 일별 자료가 부족해도 최신 기간 표본이 있으면 가격 흐름 기준의 제한적 BUY/WAIT를 제공합니다. 구매 가능한 현재 가격으로 단정하지 않습니다.

# 로그인 전용 가격 분석 채팅

> 현행 정책: [구매 판단 v3](PURCHASE-DECISION-V3.md). 아래 기존 통계는 참고 표시이며 새 엔진의 할인 에피소드 판단과 구분한다.

> 가격 정책 v2: 가격 흐름을 별도 보관하고 일별 자료 부족 시 실제 주간/월간 표본으로 보완 분석한다. 이전의 일별 자료만을 기준으로 한 호출 조건 설명보다 [기간별 이력 저장·분석 안내](PERIOD-HISTORY.md)를 우선한다. 주간/월간 값을 일별 통계로 바꾸지 않는 원칙은 유지한다.

## 이번 구현

사이트2의 그라데이션 AI 헤더, 말풍선, 제안 질문 칩, 스크롤 대화 영역, 입력창 디자인을 현재 상세 오른쪽에 적용했다. Firebase 로그인 전에는 입력창 대신 로그인 안내가 표시된다. 백엔드도 매 요청/작업 조회에서 ID 토큰을 확인한다. 운영 UID는 필요하지 않다.

Spring은 질문 분류, 통계 계산, 판단, 캐시/공유 임대, 근거 구성과 권한을 담당한다. FastAPI는 설정된 RSS의 파싱 및 근거를 바탕으로 한 Gemini 설명을 담당한다. 모델에 도구 접근 권한을 주지 않는다.

## 통계 정의

같은 다나와 상품 ID의 실제 저장된 `danawaDailyQuotes`를 최근 3년/최대 1100개 날짜까지 읽는다. 중복 날짜는 최저 표시가 하나만 사용하고, 미래 날짜·비정상 가격·다른 출처는 제외한다. 기간은 한국 날짜 기준 오늘을 포함한다.

| 지표 | 계산 및 부족 시 처리 |
|---|---|
| 30일 최저가 | 오늘~29일 전 실제 일별 최저 표시가의 최솟값. 표본 없으면 null |
| 90일 중앙값 | 오늘~89일 전 유효 날짜별 표시가를 정렬한 중앙값. 짝수 표본은 가운데 둘의 평균 |
| 최저가 대비 차이 | `(현재 카드·배송비 포함 표시가 / 30일 최저가 - 1) × 100`. 어느 쪽이 없으면 null |
| 30일 변동성 | 달력상 연속한 두 날짜의 일별 수익률(%)만 사용한 **표본 표준편차**. 최소 수익률 2개 필요. 결측일을 전일가로 채우지 않음 |
| 할인 관측 비율 | 최근 30일 유효 관측 중 **90일 중앙값보다 5% 이상 낮은 가격**의 비율. 90일 표본 최소 7개. 이 할인 기준은 서비스 정책이며 실제 행사 확인이 아님 |
| 계절성 | 과거 같은 월을 연도별로 분리해 중앙값을 제공. 과거 최소 2개 연도에서 각각 유효 날짜 3개 이상 필요. 반복 행사/향후 할인 확정으로 해석하지 않음 |

현재 가격은 캐시된 판매처 **첫 페이지**에서 카드 결제·확인된 배송비를 합산한 최저 표시가다. 원본 수집 시각이 5분 이내일 때만 신선한 현재 자료로 본다. 상품 상세 상단 최저가나 주별 최저가를 이 값으로 대신하지 않는다. 판매처 자료가 없으면 ‘판매처 가격 조회’ 후 다시 질문한다.

주간/월간 `price_history`는 별도 근거로 전달하지만 일별 표본·30일 변동성·90일 일별 중앙값으로 바꾸지 않는다. 일별 관측을 아직 쌓지 않았다면 차트는 있어도 해당 통계는 부족할 수 있다. 원본 관측 시각이 없으면 기존 저장 정책상 일별 표본이 생기지 않을 수 있다.

통계는 상품 관측 갱신 시각+한국 날짜 기준으로 프로세스 내 최대 64개/5분 재사용한다. 새 관측이 들어오면 버전이 달라져 다시 계산한다. 현재가 대비 차이만 현재 판매처 값에 맞춰 계산한다. 여러 Spring 프로세스 사이의 통계 계산 캐시는 공유하지 않으며, 최종 답변 캐시와 작업 임대는 Firestore에서 공유한다.

## 판단과 답변

판단 규칙과 구조화 응답은 [v3 설계](PURCHASE-DECISION-V3.md)을 따른다. 과거 저점과의 차이만으로 대기를 추천하는 기존 가격 신호 규칙은 제거했다.

답변은 판단 → 핵심 결론 → 주요 가격 근거 → 할인/뉴스 근거 → 주의점/기준 시각 순이다. 모델은 서버의 판정을 뒤집거나 지표를 다시 계산하지 않도록 지시한다. 형식/길이/응답 상품·모델·근거 버전을 검증하며, 형식 검증이 내용의 사실성을 완전히 보장하지는 않는다.

질문 주제에 필요한 근거가 없으면 Gemini를 호출하지 않고 서버가 부족한 지표와 판단 보류를 표시한다. 사양은 저장된 `intro`, 판매처는 최대 10개 첫 페이지 표본, 뉴스는 실제 관련 RSS 항목이 있어야 모델 설명을 요청한다. 모델 장애/할당량 초과 시 서버 통계 안내로 대체하며 자동 AI 재시도는 하지 않는다.

## 질문·문맥·재사용

- 상품 ID는 상세 URL/요청 경로에서 고정한다. raw 질문은 1~1000자로 제한한다.
- 백엔드의 키워드 규칙으로 구매 시점·가격·뉴스·사양·판매처·복합 요약을 분류한다. 무관한 질문은 사용자 지정 고정 안내를 반환하며 RSS/AI/근거 조회를 하지 않는다. 모호한 상품 질문은 짧게 되묻는다.
- ‘왜?’, ‘더 자세히’ 같은 제한된 후속 표현은 사용자별 `users/{uid}/priceAgentContexts/{productId}`에 저장된 직전 질문 유형으로 연결한다. 문맥은 30분 만료하고 계정 삭제 시 함께 정리한다. 임의의 장문 대화/예산/외부 상품 비교까지 이해하는 일반 대화 메모리는 아니다.
- 모델에는 원문 질문·전체 대화 대신 **서버가 분류한 주제와 공개 상품 근거**만 보낸다. 같은 유형 안에서는 공통 근거 요약을 반환하므로 사양별 세밀한 질문을 각각 다른 답변으로 생성하지 않는다. 분류는 의미 임베딩이 아닌 규칙 기반이며 표현 확장이 필요할 수 있다.
- 최종 답변 캐시 키는 상품 ID, 질문 유형, 실제 상품/현재가/이력/일별 통계/뉴스/신선도/한국 날짜를 포함한 근거 해시, 모델, 정책/프롬프트 버전이다. 유효기간은 5분이다. 같은 조건의 표현이 다른 질문도 같은 유형이면 재사용한다. 갱신된 근거는 새 키를 만든다.
- 만료 답변을 최신 답변으로 반환하지 않으며 공개 작업 경로로 agent 결과를 조회할 수 없다. 로그인 전용 `agent/jobs`만 허용한다. 공유 캐시에는 원문 질문·개인 대화를 저장하지 않는다.
- 채팅 말풍선은 현재 화면 메모리에만 최근 12개를 표시한다. 상품/계정 변경 시 지우며 새로고침 후 전체 채팅 복원 기능은 없다. 저장되는 문맥은 직전 질문 유형뿐이다.
- 캐시 미적중 모델 호출은 기존 사용자당 분당 5회 분석 할당량을 공유한다. 다른 사용자가 같은 공개 근거 답변을 재사용하면 추가 모델 호출은 없다. 기본 소비 제한은 모델 호출 기준이며 HTTP 요청 전체의 분산 속도 제한을 새로 구현한 것은 아니다.

## RSS 설정 — 연합뉴스

FastAPI의 `requirements-gemini.txt`에 포함된 feedparser로 연합뉴스 RSS를 파싱합니다. 설정 예시는 `backend/ai/.env.example`에 반영했습니다. 기존 `backend/ai/.env`를 사용한다면 다음 두 줄을 수정하고 환경 변수를 다시 불러온 뒤 FastAPI를 재시작하세요. 기존 환경 변수에 남은 `[]`가 설정되어 있으면 수집은 꺼져 있습니다.

```dotenv
RSS_FEEDS_JSON=[{"name":"연합뉴스","url":"https://www.yna.co.kr/rss/news.xml"}]
RSS_ALLOWED_HOSTS=www.yna.co.kr,yna.co.kr
```

최대 3개 피드, HTTPS/설정된 호스트/공개 주소 확인, 리다이렉트 금지, 피드당 256KiB, HTTP 타임아웃 및 본문 시간 제한을 사용한다. 일반 OS DNS 해석 자체의 지연까지 강제로 취소하는 독립 작업 시스템은 아니다. 뉴스 링크의 호스트도 허용 목록 또는 피드 도메인 하위 도메인이어야 한다.

원문 기사 페이지를 추가 수집하지 않고 RSS 제목/요약만 사용한다. **발행일이 있는** 최근 90일 항목만 사용하고 미래 시각 항목은 제외한다. 상품명의 모델 토큰 또는 복수 키워드가 일치한 최대 5개를 제공한다. 동일 옵션/실제 행사 적용까지 검증한 것은 아니라 관련성 한계를 표시한다. 출처·발행일·원문 링크를 응답에 포함한다.

RSS는 FastAPI 프로세스에서 15분 재사용하고 실패가 있으면 1분 뒤 다시 확인한다. 미설정·실패·일부 실패·관련 기사 없음을 구분하며 뉴스 버전은 캐시 키에 포함한다. 실제 행사 일정 데이터베이스/모든 언론사 검색/기사 본문 검증을 제공하지 않는다.

## 사용자 적용·검증

1. 기존 가상환경으로 새 의존성을 설치한다.

```powershell
cd D:\github\codyssey_final
.\.venv\Scripts\python.exe -m pip install -r backend\ai\requirements-gemini.txt
```

2. RSS를 사용하려면 위 설정을 채운다. 기존 Gemini 키와 Spring/FastAPI의 동일 모델 ID, 내부 통신 키, Firebase 서버 자격 증명을 유지한다.
3. FastAPI `.env`를 다시 불러오고 FastAPI·Spring Boot를 재시작한다. 프론트엔드도 변경을 반영한다. 실행 명령은 README를 따른다. 추가 Firestore 복합 인덱스는 필요하지 않다.
4. 비로그인 상태에서는 채팅 입력이 없고 직접 API 호출도 401인지 확인한다.
5. 로그인 후 상품 상세에서 제안 질문을 누른다. 표본이 없으면 부족 안내가 나와야 한다. 판매처 조회/운영 관측 저장/정기 수집으로 근거를 실제로 쌓아야 통계가 채워진다.
6. 무관한 질문은 지정 안내만 나오고 모델/RSS 호출이 없어야 한다. 같은 근거의 동등 질문은 agent 작업 ID/캐시를 재사용해야 한다. 후속 ‘왜?’가 현재 상품의 이전 유형으로 연결되는지 확인한다.
7. 관측/상품/뉴스/모델 변경 후 새 근거 버전과 기준 시각을 확인한다. 오래된 agent job 조회는 만료 오류 또는 진행 중 상태여야 한다.
8. RSS 미설정/오류/관련 기사 없는 피드, AI 중단, 원본 관측 시각 없는 상품, 관측 날짜 결측 사례를 확인한다. 표시 숫자가 실제 원본과 같은지 검증한다.

테스트 소스는 통계 기간·결측·할인 기준·계절 표본·분류·인증·무관 질문 차단·만료/비공개 작업·구조화 모델 출력·뉴스 캐시를 모킹해서 다룬다. 직접 실행:

```powershell
# backend/api
mvn test
# backend/ai (기존 가상환경)
..\..\.venv\Scripts\python.exe -m unittest discover -s tests
# frontend
npm run build
```

이번 작업에서는 서버 실행·의존성 설치·빌드·테스트·실제 RSS/유료 API 호출을 하지 않았다. TypeScript/Python 구문 파싱과 소스/JSON 검토만 수행했다.

## RSS 설정 읽기 보완

기존 FastAPI는 .env를 자동으로 읽지 않아 터미널에 이전에 불러온 RSS_FEEDS_JSON=[]가 남아 있으면 출처 미설정으로 보일 수 있었습니다. 이제 `app/rss_settings.py`가 실행 경로와 무관하게 `backend/ai/.env`의 RSS_FEEDS_JSON, RSS_ALLOWED_HOSTS 두 항목만 읽습니다. 로컬 파일의 명시적 설정 > 환경 변수 > 연합뉴스 기본값 순서입니다. 명시적 `[]`는 계속 수집 비활성화를 의미합니다. 다른 키와 인증 정보의 로딩 방식은 변경하지 않습니다. 설정이 달라지면 RSS 캐시를 새로 생성합니다.
