# 구매 판단 엔진 v3

## 판단 순서와 의사코드

```text
동일 상품/옵션/상태/결제/배송/판매 조건, 최신 현재가 확인
비교 불가 또는 표본 수·기간·밀도 부족 → INSUFFICIENT_DATA
최근 30/90일 중앙값, 실측 추세, 연속 일별 수익률 변동성 계산
중앙값 대비 충분히 낮았다가 회복한 독립 할인 에피소드 추출
관측 간격이 사용자 대기 한도 안이고 현재가 대비 할인 실익이 있으면 대기 근거 후보
현재가가 최근 중앙값 둘보다 상당히 높고 대기 근거가 있으면 WAIT
현재가가 최근 중앙값 둘에서 합리적이면 BUY
그 외 → INSUFFICIENT_DATA (높다는 이유만으로 WAIT 금지)
```

| 우선순위 | 조건 | 결과 | 예외 |
|---|---|---|---|
| 1 | 조건 미검증, 오래된 가격, 부족한 기록 | INSUFFICIENT_DATA | 저렴해도 비교 조건을 생략하지 않음 |
| 2 | 상당히 높은 가격 + 반복된 할인 + 대기 한도 안의 관측 간격·할인 실익 | WAIT | 과거 반복은 다음 할인 확정이나 확률이 아님 |
| 3 | 두 최근 중앙값에서 합리적인 가격 | BUY | 역대 최저가와 무관, 상승 추세도 구매 근거로 설명 가능 |
| 4 | 나머지 불명확한 가격 | INSUFFICIENT_DATA | 데이터 양은 충분해도 BUY/WAIT를 뒷받침할 근거가 부족할 수 있음 |

## 지표·설정·한계

모든 수치는 검증 전 초기 가설입니다. `purchase-timing-policy.json`이 임계값의 단일 원본입니다. 상품군별 프로필과 서버가 관리하는 상품 ID 매핑으로 적용하며, 알 수 없는 상품군은 default를 사용합니다. AI나 브라우저가 프로필을 지정하지 않습니다.

- 중앙값: 오늘 포함 30/90일의 동일 조건 관측가 중앙값. 현재가 차이=(현재가/중앙값-1)×100. 두 구간 모두 품질 기준을 만족해야 판단합니다. 누락일을 보간하거나 주간 최저가를 일별 가격으로 복제하지 않습니다.
- 품질: 각 창의 최소 관측일, 관측 범위, 관측일/90일 비율, 최근 관측 경과일을 설정으로 제한합니다. 현재가 최신성 및 비교 가능성이 확인되지 않으면 우선 유보합니다. 중복 날짜는 최소가 한 개로 정규화하며 미래/비양수 값은 제외합니다. 공급자 오류·조건 불명 값은 어댑터에서 비교 불가로 처리해야 합니다.
- 추세: 90일 실제 날짜 간격에 대한 log(가격)의 최소제곱 기울기 b, 30일 환산 변화율=(exp(30b)-1)×100. 관측 범위·밀도 통과 후에만 제공합니다. 예측 가격이 아니며 단독 WAIT 기준으로 쓰지 않습니다. 급격한 레짐 변화/단발 오류는 원본 검증 및 백테스트에서 별도 점검합니다.
- 변동성: 30일 중 실제 연속 날짜의 일별 변화율 표본 표준편차. 최소 수익률 수 미달이면 null. 변동성만으로 할인 가능성을 추정하거나 BUY 허용 폭을 무한 확장하지 않습니다.
- 할인: 90일 중앙값에서 설정 할인 폭 이상 낮은 연속 관측 구간을 하나의 에피소드로 셉니다. 누락일·아직 회복하지 않은 마지막 할인 구간은 완료된 반복 할인으로 세지 않습니다. 회복 후 별개로 시작한 최소 횟수, 시작 간격의 최대/최소 비율, 최근성, 중앙 할인 폭을 확인합니다. 관측 비율은 확률이 아닙니다.
- 대기 실익: 현재가 대비 완료 에피소드 최저가들의 중앙값 할인율. 설정 최소 실익 이상이어야 합니다. 과거 시작 간격의 최댓값이 사용자 한도(급함/보통/여유) 안이어야 합니다. 이는 다음 할인 날짜 예측이 아니며 WAIT에는 실제 가격 재확인 조건과 대기 한도를 제공합니다.
- 역대 최저가는 참고 전용이며 BUY/WAIT 분기에 사용하지 않습니다.
- 확인 행사: 현재 RSS는 제목/날짜/출처만 검증하므로 확정 행사로 승격하지 않습니다. 향후 서버에서 상품/옵션/판매처·기간·적용 자격·배송 포함 순혜택·출처를 검증하는 어댑터가 생길 때 별도 근거로 추가해야 합니다. 현재 엔진은 이 근거를 임의 생성하지 않습니다.
- 주/월간 자료: 기존 periodAnalysis로 범위와 주기를 표시하여 설명에 활용합니다. 기간 최저가만으로 일별 중앙값·변동성·독립 할인 반복을 검증할 수 없으면 확정 판단은 유보합니다.

## 대표 사례 검증 계획

| 사례 | 입력 조건 | 예상 | 이유 |
|---|---|---|---|
| A | 90일 중앙값 100, 현재 95, 과거 최저 80, 30일도 합리적, 할인 근거 없음 | BUY | 역대 최저가 회복을 기다릴 이유 없음 |
| B | 90일 100→110 상승, 현재 최근 가격대와 비슷함 | BUY | 상승 자체가 대기 이유가 아니며 최근 30/90일 합리 범위 확인 |
| C | 정상가 100, 독립 할인 3회 각 85까지 하락 후 회복, 현재 120, 간격이 한도 이내 | WAIT | 높은 가격과 관측된 반복 할인·실익이 함께 존재 |
| D | 4일 기록 | INSUFFICIENT_DATA | 신뢰할 추세·최근 가격대 부족 |
| E | 현재 80이나 옵션/판매처 조건 또는 배송비 불일치 | INSUFFICIENT_DATA | 싼 가격만으로 동일 조건이라 볼 수 없음 |

Java 테스트 소스에 A~E와 할인 없는 고가·시급성 사례를 작성합니다. 실행 결과와 구분해야 하며 이번 작업에서는 테스트를 실행하지 않습니다.

## 실제 데이터로 조정

상품/시간을 분리한 rolling-origin 검증을 사용합니다. 판단 당시까지의 정보만 입력하고 이후 7/14/30일 동일 조건 총액, 실제 구매 가능 재고와 할인 적용 여부를 기록합니다. BUY의 이후 가격 하락 손실, WAIT의 가격 상승·기한 초과·할인 미발생 비용, 유보 비율을 상품군별 비교합니다. 관측되지 않은 미래값은 실패/성공으로 채우지 않습니다. 사용자 시급성별 비용을 따로 평가하고 최소 표본이 없는 상품군은 기본 프로필을 유지합니다. 확률은 교정된 별도 모델 없이 제공하지 않습니다. 설정 변경은 evidenceVersion에 포함되어 기존 캐시를 무효화합니다.

## 프롬프트와 구조화 출력

실제 전송 시스템 프롬프트는 `backend/ai/app/prompts/price_agent.txt` 한 곳입니다. 숫자 임계값을 프롬프트에 중복하지 않습니다. 기존 구현은 Google SDK가 아니라 httpx로 Gemini generateContent REST API를 호출합니다. 공식 API의 responseMimeType + responseJsonSchema를 유지하고 Pydantic으로 길이·타입·enum·추가 필드를 검증하며, 서버 decision/wait_condition과 일치하는지도 검증합니다. JSON 요청 문장만으로는 형식 보장이 없고, JSON Schema도 수치의 진실성이나 의미적 정합성을 보장하지 않으므로 업무 검증이 필요합니다. 실패 시 유료 재호출 없이 서버 결과를 반환합니다. 구성한 GEMINI_MODEL의 구조화 출력 지원 및 실제 연결은 사용자가 실행하여 확인해야 합니다.

출력 필수 필드: decision(enum), headline(string), reasoning(string[]), risks(string[]), wait_condition(string|null; 서버 지정), data_limitations(string[]), answer(string). 호환 화면을 위한 기존 conclusion/priceReasons/verdict는 서버가 동일 결과에서 파생합니다.

분류: 명시적 무관/주입 질문은 Firestore·RSS·AI 전에 고정 안내, 불명확한 질문은 짧은 확인, 구매/가격/뉴스/사양/판매처는 정규화 intent로 처리합니다. 후속 질문은 선택 상품과 30분 내 직전 intent를 연결합니다. 원문 대화를 공유 캐시에 저장하지 않습니다. 표현이 달라도 같은 상품·intent·시급성·근거·정책·모델이면 캐시를 재사용하며 데이터 갱신 시 무효화됩니다. 복잡한 지시 대명사/여러 조건의 대화는 현재 제한적이며 임의 해석하지 않습니다.

현재 Danawa는 판매처 옵션·재고 및 과거 배송 조건을 검증하지 못합니다. 이 어댑터의 비교 가능성은 false로 유지합니다. 따라서 실제 응답은 충분한 기간 이력이 있어도 유보할 수 있습니다. 검증 없는 값을 true로 변경해서 BUY를 강제하면 안 됩니다.

참고: https://ai.google.dev/gemini-api/docs/structured-output , https://ai.google.dev/api/generate-content

## 실행·확인 방법

기존 환경 변수 설정 후 Spring Boot와 FastAPI를 재시작하고 프론트엔드를 새로고침합니다. 추가 라이브러리나 Firebase 인덱스 배포는 필요하지 않습니다. 정책 JSON 변경도 Spring 재시작이 필요합니다. 로그인 후 상품 상세에서 시급성을 바꾸어 질문하고 Network의 응답에서 decision, wait_condition, data_limitations를 확인합니다. 실제 Danawa 조건 미검증 시 유보가 정상입니다.

사용자가 실행할 검증 명령:

```powershell
cd D:\github\codyssey_final\backend\api
mvn "-Dtest=PurchaseTimingEngineTest,PriceAgentPolicyTest,PriceAgentControllerTest" test
cd D:\github\codyssey_final\backend\ai
..\..\.venv\Scripts\python.exe -m unittest discover -s tests -p test_price_agent.py
cd D:\github\codyssey_final\frontend
npm run build
```

이는 실행 안내이며 이번 변경에서 수행한 테스트 결과가 아닙니다. A~E는 합성된 테스트 입력으로 기대 분기를 검증하는 사례이며 실제 가격 데이터에 대한 성능 검증을 대신하지 않습니다.
