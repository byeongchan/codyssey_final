# 목표 가격·인앱 알림 실행 안내

상품별 목표가 설정, 켜기/끄기, 삭제, 알림 목록과 읽음 처리를 추가했다. 가격은 기존 fixture이며 계정·설정·알림은 Firebase Emulator에 저장한다. 실제 쇼핑몰 수집·이메일·웹 푸시는 연결하지 않았다. 설치·실행·테스트는 수행하지 않았다.

## 실행

1. [Firebase 안내](FIREBASE.md)의 에뮬레이터·API·프론트엔드를 실행한다. 신규 npm 의존성은 없다.
2. 로그인 후 상품 상세의 ‘목표 가격 알림’에서 목표가를 등록한다. 상품마다 사용자별 설정 하나를 저장하며 중복 POST는 같은 설정을 갱신한다.
3. 등록·설정 변경 직후 현재 가격을 확인한다. 헤더의 종 아이콘 또는 ‘알림함 보기’에서 알림과 설정을 확인한다.
4. ‘가격 다시 확인’은 본인 설정만 점검하는 POST 요청이다. GET 조회만으로 알림을 생성하지 않는다.

자동 점검도 사용하려면 기존 API를 종료하고 같은 터미널에서 다음 환경 변수를 추가해 재시작한다. Firebase 환경 변수와 내부 서비스 키는 기존 설정을 유지한다.

```powershell
cd D:\github\codyssey_final\backend\api
$env:ALERT_SCHEDULER_ENABLED = 'true'
mvn spring-boot:run
```

자동 점검은 시작 10초 후 첫 실행, 이후 작업 완료 기준 60초 간격이다. 활성 설정을 최대 100개씩 순회한다. 100개가 넘으면 다음 실행에서 다음 페이지를 점검한다. 마지막 페이지 이후 처음으로 돌아온다. 기본값은 false이며, 이 경우 등록/변경 직후 판정과 수동 확인만 동작한다. 켜져 있으면 브라우저가 닫혀도 API·에뮬레이터가 실행 중인 동안 점검한다. 화면은 실시간 푸시를 구독하지 않으므로 새로고침으로 새 알림을 확인한다.

`firebase/firestore.indexes.json`에 활성 알림 collection-group 조회용 인덱스 설정을 추가했다. 에뮬레이터를 다시 시작한다면 기존 계정/알림을 보존하도록 export/import 절차를 따른다. 실제 클라우드 인덱스 배포는 수행하지 않는다.

## 판정·중복 방지 규칙

- 동일 상품 옵션·KRW·재고 있음·배송비 확인·관측 24시간 이내인 판매처의 확정 최저가를 사용한다. 미래 관측은 제외한다. 조건부 카드/쿠폰 할인은 차감하지 않는다.
- `현재 확정가 <= 목표가`가 최초로 성립하면 알림을 만든다. 이후 같은 조건을 유지하는 새 관측이나 같은 관측의 재처리는 추가 알림을 만들지 않는다.
- 목표가 초과의 더 최신 관측을 확인하면 미충족으로 바뀐다. 다시 목표가 이하의 더 최신 관측을 확인하면 새 알림을 만든다.
- 품절·배송비 미확인·오래된 가격·상품 미존재는 판정을 보류한다. 기존 충족 상태를 미충족으로 바꾸지 않으므로, 데이터 장애 복구만으로 재알림이 발생하지 않는다.
- 같은 시각과 이전 시각의 관측은 무시한다. 가격 변경 테스트에서는 관측 시각도 함께 증가시켜야 한다.
- 목표가나 활성 상태를 실제로 변경하면 새 판정 구간을 시작한다. 켜기로 변경하거나 목표가를 높여 이미 조건이 충족되면 즉시 한 번 알린다. 같은 설정을 반복 저장하면 판정 상태를 초기화하지 않는다.
- 설정 삭제는 과거 알림을 지우지 않는다. 삭제 후 재등록은 새 설정 세대로 취급한다. 읽음 처리는 반복해도 최초 readAt을 유지한다.
- 알림 생성, 이벤트 순번, 마지막 관측·충족 상태를 같은 [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions)에서 기록한다. 여러 탭·스케줄러·재시도가 겹쳐도 동일한 상태 전환을 하나의 알림으로 기록하도록 구성했다. 실제 동시성 검증은 아래 절차로 수행한다.

## 사용자 직접 검증

1. 소니 상품의 최초 목표가를 **400,000원**으로 등록한다. fixture의 확정 최저가는 384,900원이므로 새 알림이 1개 증가해야 한다.
2. 가격 다시 확인을 반복하고 두 탭에서 동시에 눌러도 증가량이 0인지 확인한다.
3. 읽음 처리 후 재조회하면 읽음이 유지되어야 한다. 같은 알림을 다시 PATCH해도 readAt은 바뀌지 않아야 한다.
4. 목표가를 **380,000원**으로 바꾸면 미충족이다. 이후 400,000원으로 바꾸면 설정 변경에 따른 새 알림이 1개 증가해야 한다.
5. 끄기 상태에서는 재확인해도 알림이 생성되지 않는다. 다시 켜면 현재 가격이 조건을 충족할 경우 1개 증가해야 한다.
6. Bob으로 로그인하면 Alice의 설정·알림은 보이면 안 된다. Alice의 알림 ID를 Bob의 토큰으로 읽음 처리하면 404여야 한다.
7. 미로그인 GET/POST/PATCH/DELETE는 401이어야 한다. 음수·0·소수·문자열·1조 초과 목표가는 400이어야 한다.
8. 전체 품절 상품은 설정을 저장할 수 있지만 알림을 만들면 안 된다. README의 만료 기준 시각으로 재기동해도 오래된 가격으로 알림을 만들면 안 된다.

가격 자체의 ‘미충족 → 충족’을 확인하려면 다음 순서로 진행한다. 먼저 fixture 파일을 따로 복사해 원본을 보관하고, 에뮬레이터는 계속 실행해 설정과 판정 상태를 유지한다.

1. 기본 소니 목표가 400,000원·현재가 384,900원에서 최초 알림을 확인한다.
2. `fixtures/catalog.json`의 referenceTime을 `2026-10-22T03:01:00Z`로 변경한다. `fixtures/prices.json`에서 소니의 배송비가 확인된 재고 있는 모든 판매처 상품가를 400,000원보다 높게 변경하고, 해당 판매처 observedAt도 같은 시각으로 바꾼다.
3. API를 재시작하고 가격 다시 확인으로 미충족 판정을 저장한다. `FIXTURE_REFERENCE_TIME`이 이전 시각으로 남아 있다면 제거하고 재시작한다.
4. 기준 시각과 해당 판매처 observedAt을 `2026-10-22T03:02:00Z`로 증가시키고 상품가를 원래 수준으로 낮춘다. API 재시작 후 확인하면 새 알림이 1개 증가해야 한다.
5. 원본 fixture를 복원하면 시각이 뒤로 돌아가므로, 테스트 설정을 삭제 후 재등록해 새 판정 구간으로 시작한다. 기존 알림 이력은 남는다.

설정 저장과 가격 평가는 별도 단계다. 저장 후 평가에서 503이 발생했다면 설정 자체는 저장되었을 수 있다. 설정 재조회 또는 같은 요청 재시도로 복구하며, 거래 상태가 원자적으로 갱신되어 재시도로 알림을 중복 생성하지 않도록 했다. 네트워크 중단·재시도 동작은 실제 에뮬레이터에서 확인해야 한다.

## 테스트 명령

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
```

작성한 테스트는 임계값·반복·재진입·역순·무효 가격·사용자 범위·목표가 입력 검증·부분 수정 계약을 확인한다. 실행하지 않았다. 실제 Firestore 트랜잭션 경합·복구·자동 점검은 위 수동 검증 대상이다. fixture 저장 완료 이벤트의 자동 평가는 [저장 알림 안내](SNAPSHOT-ALERTS.md)를 따른다. 외부 푸시, 가격 실수집 트리거, 클라우드 작업 큐·보존 기간 정책은 후속 범위다.
