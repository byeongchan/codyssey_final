# 실제 다나와 상품 찜

## 화면 사용

1. Firebase 계정으로 로그인한다. 로그인하지 않은 상태에서 상품 하트를 누르면 기존 로그인 화면을 연다. 로그인 후 원래 화면으로 돌아와 다시 눌러 저장한다.
2. 검색·카테고리·홈 상품 카드의 오른쪽 하트 또는 상세의 찜하기 버튼을 누른다. 저장된 상품은 하트가 채워지며 다시 누르면 해제한다.
3. 상단 하트를 눌러 찜 목록을 연다. 최근 저장순으로 페이지당 최대 12개를 표시한다. 목록의 하트로 해제하고 상품을 눌러 동일 상품 ID의 상세를 연다.
4. 새로고침·재로그인 뒤에도 Firestore에 저장한 목록을 다시 불러온다. 다른 탭·기기에서 변경했다면 목록 새로고침으로 반영한다. 실시간 구독은 하지 않는다.

## 저장·권한

- 실제 상품 전용 컬렉션은 `users/{검증한 UID}/danawaWishlist/{다나와 상품 ID}`다. 기존 fixture wishlist와 섞지 않는다.
- Firebase ID 토큰으로 로그인 사용자를 확인하며 UID를 브라우저 입력에서 받지 않는다. 모든 로그인 사용자가 이용하며 운영 UID 제한은 없다.
- GET `/api/v1/me/danawa/wishlist`, PUT/DELETE `/api/v1/me/danawa/wishlist/{productId}`를 사용한다. PUT은 `{}` 또는 `{ "catalogProductId": "검색 대표 상품 ID" }`만 받는다.
- 제목·이미지·가격·원본 관측 시각은 서버에 저장된 상세 캐시 또는 검색 카탈로그에서만 읽는다. 브라우저가 전송한 제목·가격은 저장하지 않는다. 검색 대표 상품과 최저 옵션 ID가 다르면 서버의 variants에서 소속을 확인한다.
- 가격은 **저장 당시 표시가**다. 찜 목록을 최신 가격이라고 표시하지 않으며 상세 조회 때 현재 반환 자료를 확인한다. 찜하기/해제/목록 조회는 Reef·Gemini를 호출하거나 가격 관측을 생성하지 않는다. 상품 상세 이동은 기존 상세·가격 이력 API 정책을 따른다.
- 사용자당 최대 100개. 생성·삭제와 사용자 루트의 `danawaWishlistCount`를 같은 Firestore 트랜잭션으로 갱신한다. 중복 저장은 원래 저장 시각과 개수를 유지하고, 반복 삭제는 개수를 추가 차감하지 않는다.
- 계정 삭제 마커가 있으면 찜 변경을 차단한다. 계정 삭제 단계에서 새 컬렉션도 정리한다. 직접 Firestore 규칙은 기존 서버 전용 deny 정책을 유지한다.
- 목록은 전체 최대 100개를 읽어 화면에서 페이지를 나눈다. 새로고침·변경 이후의 목록 조회에는 Firestore 읽기가 발생한다. 목록을 브라우저 영구 저장소에 보관하지 않고 계정 변경 시 상태와 진행 요청을 정리한다.
- 쓰기 응답이 유실되면 실제 저장 여부가 불명확하므로 재변경 전에 목록 재조회를 요구한다. 다른 탭과 동시에 바꾼 경우에도 PUT/DELETE 자체는 멱등이며 다음 목록 조회에서 서버 상태로 맞춘다.

브라우저에만 남은 과거 검색 결과여서 서버에 상품 정보가 없다면 저장할 수 없다는 안내가 나온다. 검색 새로고침 아이콘으로 서버 자료를 확인하거나 상품 상세를 조회한 뒤 저장한다. 자동 유료 재수집은 하지 않는다.

## 적용·직접 검증

추가 패키지·Firestore 복합 인덱스·규칙 배포는 필요하지 않다. 기존 Firebase 서비스 계정 설정으로 Spring Boot를 재시작하고 프론트엔드를 새로고침한다.

```powershell
cd D:\github\codyssey_final\backend\api
mvn spring-boot:run
```

확인 순서:

- 비로그인 상태에서 홈/검색/상세가 열리고 하트를 누르면 로그인 화면으로 이동하는지 확인한다.
- 로그인 후 검색 카드에서 찜 → 상단 하트 목록 → 상품 상세 이동 → 상세 찜 해제까지 확인한다.
- 카드가 최저 옵션 ID로 이동하는 경우 찜 목록도 같은 ID인지 확인한다.
- 새로고침/재로그인 뒤 유지되는지, 다른 계정으로 로그인하면 이전 계정 목록이 보이지 않는지 확인한다.
- 찜 목록이 13개 이상이면 12개 단위 페이지가 표시되는지 확인한다.
- Firestore 연결 실패 때 오류와 목록 다시 불러오기가 표시되는지 확인한다. 실패한 하트 변경을 성공처럼 표시하지 않아야 한다.
- 찜 조작만으로 Node의 외부 요청 횟수가 늘지 않는지 확인한다.
- 기존 계정 삭제 검증은 실제 삭제 의도가 있는 별도 테스트 계정에서만 수행한다.

테스트/빌드 명령은 사용자가 직접 실행한다.

```powershell
cd D:\github\codyssey_final\backend\api
mvn test

cd D:\github\codyssey_final\frontend
npm run build
```

작성한 테스트 소스는 인증 UID 전달, 입력 메타데이터 거부, 서버 상품 스냅샷 사용, 중복 저장/해제, 계정 삭제 및 저장 개수 제한을 다룬다. 이번 작업에서 서비스 실행·빌드·테스트·실제 Firebase 쓰기·유료 API 호출은 수행하지 않았다.
