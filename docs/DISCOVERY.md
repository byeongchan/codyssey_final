# 합성 리뷰 예시와 평균 대비 특가

실제 리뷰·Reef·Gemini 호출 없이 fixture만 사용한다. 실행·빌드·테스트는 수행하지 않았다.

## 리뷰 예시

`fixtures/reviews.json`을 API 시작 시 읽고 스키마·상품 참조·중복 ID·별점·집계 시각·합성 표시·태그를 검증한다. 파일 오류나 누락 시 API 시작을 중단한다. `FIXTURE_DIR`를 따로 지정했다면 해당 폴더에도 이 파일이 필요하다. 리뷰별 최대 1000자, 상품별 최대 50개 예시만 허용한다.

`GET /api/v1/products/{id}/reviews`는 `{data,meta}`를 반환한다. 상품 상세에 리뷰 예시 영역을 연결했고, 구매 비서의 리뷰 질문도 해당 영역으로 안내한다. 응답은 공개 조회이며 Firebase·FastAPI 실행 여부에 의존하지 않는다.

| 상품 | 상태 | 현재 합성 표본 |
| --- | --- | --- |
| 소니 (`sony-xm5-black`) | AVAILABLE | 4개, 평균 3.50/5, 긍정 2·중립 1·부정 1 |
| 맥북 (`macbook-m3-16`) | INSUFFICIENT_DATA | 1개, 원문·별점만 제공하며 장단점 요약 보류 |
| 워치 (`watch-10-42`) | UNSUPPORTED | 미지원. 별점 평균은 null |
| 품절 예시 (`sold-out-demo`) | EMPTY | 리뷰 지원 상태이나 표본 없음. 별점 평균은 null |

긍정은 4~5점, 중립은 3점, 부정은 1~2점의 단순 별점 분류다. 감정 분석 결과가 아니다. 평균은 실제 예시 별점 합계/표본 수다. 장단점은 fixture에 수작업으로 작성한 `pros`/`cons` 태그의 표본 등장 횟수 상위 3개이며, 동률은 태그명순이다. 태그가 여러 개일 수 있으므로 서로 배타적인 비율로 해석하지 않는다. 표본 3개 미만이면 장단점 목록을 비운다.

루트 `updatedAt`은 예시 집계 시각이다. `FIXTURE_REFERENCE_TIME`과 비교해 정확히 24시간까지 유효하고 초과하면 만료다. 표본이 있는 지원 상품은 만료 시 STALE로 반환하고 장단점 요약을 보류한다. 이전 평균·원문은 유지하되 화면에 이전 집계임을 표시한다. 미지원/빈 표본은 해당 상태를 유지한다. `meta.source=fixture`, `meta.synthetic=true`, `data.method=fixture-rating-and-authored-tags-no-ai`를 제공한다. 알려지지 않은 상품은 404다.

## 평균 대비 특가

헤더의 추세 아이콘 또는 `?view=deals`에서 확인한다. 상품을 누르면 상세로 이동하고 뒤로 가면 특가 목록으로 돌아온다.

`GET /api/v1/deals?cursor=0&limit=20` → `{items,nextCursor,criteria,meta}`. `limit`은 1~50이고 cursor는 결과의 시작 위치 정수다. 응답의 문자열 `nextCursor`를 다음 요청에 사용한다. 결과가 없으면 200과 빈 배열을 반환한다. 인증은 필요 없다.

선정 기준:

1. fixture 기준 시각의 한국 날짜를 포함한 최근 30일에서 일별 대표값을 조회한다. 누락된 날을 생성하거나 연속 관측으로 간주하지 않는다.
2. 확보한 관측일이 최소 7일이고 마지막 이력이 유효해야 한다. 최신 이력의 유효성은 기존 가격 도메인과 동일하게 해당 한국 날짜 종료 후 24시간 기준이다.
3. 현재 가격은 재고 있음·KRW·배송비 확인·24시간 이내·미래 아님을 만족하는 판매처의 최저 확정 비교가다. 배송비와 무조건 할인만 반영한다. 조건부 쿠폰, 배송비 미확인, 품절, 만료 판매처는 제외한다.
4. 평균은 확보한 일 대표값 합계/실제 관측일 수다. `현재가 × 관측일 수 × 100 ≤ 가격 합계 × 98`일 때만 포함한다. 표시 반올림으로 2%가 되는 상품을 잘못 넣지 않는다. 평균 대비 차이는 `(평균-현재가)/평균×100`이며 API는 소수 12자리까지 계산하고 화면은 2자리로 표시한다.
5. 평균 대비 차이 내림차순, 동률 상품 ID 오름차순이다. 카드에 현재가·평균가·실제 관측일·관측 범위·현재가 관측 시각을 표시한다.

`criteria={windowDays:30,minimumObservedDays:7,minimumBelowAveragePercent:2}`를 응답에 명시한다. 실제 할인 행사, 정가 대비 할인율, 전체 시장 최저가, 미래 가격 예측을 의미하지 않는다. 현재 fixture 전체를 기준으로 선정하며 검색/카테고리 필터는 적용하지 않는다. 빈 결과의 `meta.updatedAt`은 null이고, 반환하는 오래된 현재가가 없으므로 `meta.stale=false`다.

## 직접 실행·검증

의존성·환경 변수 추가는 없다. 기존 README 환경에서 API와 프론트엔드를 재시작한다. 리뷰·특가만 확인할 때 Firebase와 FastAPI는 필요 없지만, 로그인·알림·채팅·기존 구매 분석을 함께 확인하려면 기존 서비스도 실행한다.

API 터미널:

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
mvn spring-boot:run
```

별도 프론트엔드 터미널:

```powershell
cd D:\github\codyssey_final\frontend
npm run build
npm run dev -- --host 127.0.0.1 --port 5173
```

수동 확인:

- 소니 상세: 합성 표시, 4개 원문, 평균 3.50, 긍정/중립/부정 2/1/1, 장단점별 표본 수를 확인한다.
- 맥북·워치·품절 예시 상세: 표본 부족·미지원·빈 표본 문구가 구분되고 장단점 요약을 만들지 않는지 확인한다.
- 특가 버튼: 선정 기준과 근거가 보이고 맥북(이력 부족)과 품절 예시가 제외되는지 확인한다. 카드 → 상세 → 뒤로 가기, 새로고침, 모바일·다크 모드도 확인한다.
- 브라우저 네트워크 또는 API 클라이언트: `/deals?limit=51`, `/deals?cursor=-1`은 400, 알려지지 않은 상품의 리뷰는 404, 성공 응답은 fixture/synthetic 표시를 확인한다.
- API를 종료한 후 API 터미널에 `$env:FIXTURE_REFERENCE_TIME='2026-10-24T03:00:00Z'`를 설정하고 재시작한다. 소니 리뷰는 이전 집계·요약 보류, 특가는 빈 결과여야 한다. 검증 후 API를 종료하고 `Remove-Item Env:FIXTURE_REFERENCE_TIME`으로 원래 기준을 복원한 뒤 재시작한다.
- API를 내려 화면을 열어 리뷰와 특가의 오류·재시도 UI가 동작하는지 확인한다. 리뷰 실패가 이미 불러온 상품 상세나 가격 영역을 가리지 않아야 한다.

작성한 테스트는 합성 리뷰 검증·별점/태그 표본 집계·미지원/빈 표본/부족/만료 구분·특가 정확한 2% 경계·큰 금액·표본 부족/만료/가격 없음 제외·조회 범위 오류 및 OpenAPI 경로/참조를 확인한다. 실행 결과는 아직 없다. 실제 리뷰 공급자·저작권/이용 조건 확인·원문 수집·Gemini 요약·리뷰 변경 감지는 후속 작업이다.
