# 중고 AI 구매 비서

중고 매물 상세 아래에서 로그인 후 매물 요약, 조회 매물 가격 비교, 판매자에게 확인할 질문을 요청합니다. 기존 다나와 가격 이력·뉴스 상담과 별도 경로로 동작합니다.

## 근거와 제한

- 브라우저는 검색 작업 ID와 후보 매물 식별자만 전달합니다. 가격·설명·통계는 서버가 저장된 `liveDisplayCache`에서 읽습니다. 임의 가격 입력은 거부합니다.
- 선택한 매물 상세와 현재 표시 조건에 포함되는 최대 48개 후보를 사용합니다. 중고나라 2페이지와 당근 결과를 위해 검색 근거는 최대 3개입니다. 목록 없이 상세로 직접 진입하면 매물 요약·질문 안내만 제공합니다.
- 같은 플랫폼·매물 ID 중복과 선택 매물 자신을 제외합니다. 검색 시각이 없거나 하루가 지난 후보는 비교에서 제외합니다.
- 현재 데이터에는 구조화된 모델·상태·구성품 식별 정보가 충분하지 않습니다. 첫 구현은 **제목이 완전히 같은 판매 중 유료 후보**만 참고 집계합니다. 후보 3개 이상일 때 최저·중앙·최고 희망 가격을 서버에서 계산합니다. 동일 옵션·상태가 검증된 비교나 전체 시세가 아니며, 플랫폼을 넘나드는 동일 물건 재등록은 확인하지 못합니다.
- 나눔·가격 미확인·선택 매물의 오래된 정보는 가격 수준 판단을 보류합니다. 중고나라의 판매 상태가 미제공되면 거래 상태 확인이 필요하다고 안내합니다.
- 구매 판단은 서버의 `비교 자료 부족`, `거래 상태 확인 필요`, `추가 확인 필요`를 유지합니다. 현재 버전은 구매 추천을 확정하지 않습니다.
- AI는 전달한 자료만 사용합니다. 외부 매물·뉴스·신품 가격·제품 지식 검색과 이미지 판독을 하지 않습니다. 미래 가격·실거래가·사기 여부·협상 금액을 단정하지 않도록 지시합니다.
- 판매자 설명 인용은 원문에 실제 포함되는지 Python과 Java에서 확인합니다. AI 답변의 새로운 숫자도 거부합니다. 자연어 요약 자체의 정확성은 보장하지 않으며 화면에 판매자 주장과 자료 한계를 명시합니다.

## API와 데이터 흐름

`POST /api/v1/me/used/agent/{provider}/{productId}/messages`

본문은 `message`, `searches: [{provider,id}]`, `candidates: [{provider,productId}]`, `history: [{role,content}]`, 후속 질문의 `evidenceVersion`입니다. 질문은 1,000자, 최근 문맥은 6개로 제한합니다. `system` 역할이나 근거 외 필드는 허용하지 않습니다.

서버가 근거를 계산한 뒤 내부 인증이 적용된 `POST /internal/used-agent/analyze`를 호출합니다. Gemini는 서술과 판매자 설명 인용을 반환하고, 통계·판단·한계·질문 목록은 서버 결과를 사용합니다. Gemini에 계정 UID·이메일이나 구조화된 판매자 식별자·이미지 URL을 보내지 않습니다. 판매자가 설명에 쓴 개인정보나 사용자가 질문에 입력한 개인정보는 문맥에 포함될 수 있습니다.

기존 `AnalysisQuota`를 사용하므로 기존 분석과 합산해 사용자당 1분 5회 제한입니다. 탈퇴 진행 중인 계정은 차단합니다. 응답은 `no-store`이며 대화 원문·개인별 답변을 Firestore나 공용 캐시에 저장하지 않습니다. 최근 대화는 현재 화면 메모리에서만 관리합니다.

매물·지역·조회 조건·상세 갱신으로 근거가 바뀌면 UI 대화를 초기화합니다. 상담 중 서버의 저장 근거가 변경되면 후속 질문에 409를 반환하고 초기화하도록 안내합니다. AI 장애 시 서버가 계산한 근거·한계·확인 질문을 표시합니다.

## 반영과 사용자 확인

기존 API/AI의 `AI_URL`, `INTERNAL_API_KEY`, `AI_PROVIDER=gemini`, `GEMINI_MODEL`, `GEMINI_API_KEY` 설정을 사용합니다. API와 AI 서비스 양쪽 모델 설정이 같아야 합니다. API·AI 서비스를 재시작하고 프론트엔드를 갱신합니다. 새 Firebase 컬렉션·인덱스·Storage 설정이나 패키지 설치는 필요하지 않습니다.

실행·빌드·테스트·상품 API·Gemini 호출은 수행하지 않았습니다. 아래 목 테스트를 추가했습니다.

- `UsedAgentPolicyTest`: 본인·중복·판매 완료·다른 제목 제외, 부족한 표본·오래된 근거·거래 상태 미확인 처리.
- `UsedAgentControllerTest`: 임의 가격·시스템 역할 주입을 저장소 읽기 전에 거부.
- `test_used_agent.py`: 외부 도구 미전달, 원문 없는 인용·근거 없는 숫자 거부.

사용자 확인 항목: 비로그인 안내, 일반 질문/후속 질문, 중고나라·당근 및 상세 직접 진입, 부족한 표본, 판매 완료, 원문 인용, 상세 갱신과 대화 초기화, 자료 변경 409, AI 미설정/실패 시 대체 표시, 사용자 요청 제한, PC·모바일 화면.

## 검색 결과 구매 비서와 이상 저가 제외

목록 우측의 ‘두 플랫폼을 한눈에’, ‘안전 거래 체크’ 카드를 제거하고 검색 결과용 구매 비서를 배치했습니다. 기존 원본 가격 요약은 구매 비서 안의 **제외 처리 후 가격 요약**으로 통합했습니다. 로그인 후 검색 완료 시 서버 통계를 자동 조회하며, 이 요약 조회는 Gemini 호출이나 분석 쿼터를 소비하지 않습니다. 실제 대화만 기존 AI 요청 제한을 사용합니다.

- `/api/v1/me/used/agent/search/summary`: 저장된 검색 자료의 정제 통계.
- `/api/v1/me/used/agent/search/messages`: 같은 근거를 이용한 AI 상담.
- 검색 3개 스냅샷, 현재 플랫폼 탭·가격 필터에 맞는 최대 1,200개 식별자만 전달합니다. 서버가 저장된 매물과 대조해 읽고 추가 상품 검색을 하지 않습니다. 실제 페이지 번호와 무관하게 조회된 결과 중 현재 표시 조건에 맞는 전체 후보를 분석합니다.
- 플랫폼별 ID 중복 제거 후 나눔·가격 미확인·예약·판매 완료를 제외합니다. 판매 상태 미확인은 별도 개수로 안내하며 포함합니다.
- 유효 가격이 5개 이상이고, 1,000원 이하 저가 군과 10,000원 이상 참조 군 사이가 50배 이상 벌어지며, 참조 군이 최소 3개이고 저가 군보다 작지 않을 때 저가 군을 제외합니다. 가장 큰 단절 지점을 사용합니다. 예: 10·100·50,000·50,000·100,000원은 앞의 2개를 제외합니다. 표본 부족·전체적으로 저렴한 결과·저가 다수 집단에는 이 규칙을 적용하지 않습니다.
- 실제로 허위매물인지 판별한 것은 아닙니다. 정상적인 저가·부품·예약금 등이 제외되거나 의심 매물이 남을 수 있으므로 제외 개수·기준·사유를 공개합니다. 제외 매물 미리보기는 최대 40개입니다. 원래 검색 목록의 매물을 삭제하거나 숨기지는 않습니다.
- 정제 후 3개 이상일 때 최저·평균·최고·중앙값, 중앙 50% 가격 범위와 1·2·5 단위 가격 구간별 개수·비중을 계산합니다. 최빈 구간 동률은 모두 표시합니다. 서로 다른 모델·용량·상태가 섞일 수 있으므로 전체 시세나 적정 구매가로 해석하지 않습니다.
- 표본이 부족하면 통계를 생략합니다. 검색 조건·갱신·플랫폼 탭·가격 필터 변경 시 요약과 대화를 초기화합니다. 최초 질문도 화면에 표시한 요약 버전과 일치하는지 검사합니다.

`UsedSearchAnalysisTest`에 이상 저가·정상 저가·부족한 표본·중복·판매 상태·최빈 구간 동률 사례를 추가했습니다. 실행·빌드·테스트·유료 API 호출은 수행하지 않았습니다. 반영 시 API와 AI 서비스를 재시작하고 프론트엔드를 갱신합니다.
## 상세 매물의 가격 위치와 확인 사항

상세 상담은 ‘비교 자료 부족’을 대표 문구로 내보내는 대신, 상세 정보에서 확인할 항목과 검색 가격대에서의 위치를 설명합니다. 앞서 조회한 현재 표시 조건의 전체 후보(최대 1,200개)를 사용하며 선택 매물 자신은 통계에서 제외합니다.

이상 저가·거래 완료 등을 제외한 같은 제목 후보가 3개 이상이면 우선 참고하고, 그렇지 않으면 전체 검색 결과의 정제 가격대를 참고합니다. 후자는 같은 모델의 적정 시세로 해석하지 않습니다. 중앙 50% 가격 범위 안/아래/위인지 서버가 계산하고, 가격 차이가 상태·하자·구성품으로 설명되는지 확인하도록 안내합니다. 1~2개의 후보도 실제 관측 가격으로 표시하되 ‘소수 후보의 참고 비교’로 설명하며 가격 적절성을 확정하지 않습니다.

선택 매물 자체가 일반 가격대보다 극단적으로 낮으면 전체 상품 가격인지, 부품·예약금·가격 협의용 표시인지 확인하도록 합니다. 가격이 없거나 상세 조회 시각이 오래되었으면 수치 판단을 만들지 않고 상세 설명과 확인 사항을 정리합니다. 직접 상세 진입으로 검색 후보가 없는 경우도 같은 방식입니다. 서버가 계산한 가격 검토와 확인 목록은 AI 장애 시에도 표시합니다.

관련 정책 테스트를 변경·추가했으며 실행·빌드·테스트·실제 API 호출은 하지 않았습니다. API·AI 재시작과 프론트엔드 갱신이 필요합니다.
## 답변 생성 대기 표시

중고·다나와 구매 비서는 요청이 진행되는 동안 회전 로딩 애니메이션과 ‘잠시만 기다려주세요. 답변을 생성하는 중입니다.’를 화면에 표시합니다. 완성된 Gemini 응답만 대화 답변으로 추가합니다. 생성 실패·시간 초과 시 서버 대체 응답을 AI 답변처럼 추가하지 않으며 재시도 안내와 입력한 질문을 유지합니다. 중고 목록의 자동 가격 통계는 AI 생성과 별도의 서버 계산이므로 그대로 제공됩니다.

Gemini 생성 대기는 60초, 응답 읽기 제한은 75초, API 내부 AI 요청 대기는 85초로 늘렸습니다. 무한 로딩이나 유료 요청 자동 반복은 하지 않습니다. 변경은 코드 확인만 했으며 실행·테스트하지 않았습니다. API·AI 재시작과 프론트엔드 갱신이 필요합니다.
## 매물 지역 정보의 수치화

검색 구매 비서의 가격 요약 아래에 전체 및 중고나라·당근 각각의 지역 제공/미제공 건수·비율을 표시합니다. 플랫폼별로 빈도가 높은 지역명 최대 20개와 각 건수·비율, 나머지 지역 제공 건수도 확인할 수 있습니다. 같은 내용은 상세 상담의 검색 분포 근거와 Gemini에 전달됩니다.

집계 대상은 현재 분석 대상인 신선한 검색 스냅샷과 화면 필터에 포함된 후보이며 플랫폼+매물 ID로 중복 제거합니다. 가격 분석의 나눔·예약·이상 저가 제외 전 자료를 집계하므로 가격 분석 건수와 다를 수 있습니다. 전체 집계의 비율은 전체 건수, 플랫폼별 비율은 해당 플랫폼 건수가 분모입니다. 소수점 첫째 자리로 반올림하며 결과 0건의 비율은 0입니다.

null·빈 문자열·지역 정보 미제공 등 명시적 미제공 값은 별도 집계합니다. 주소는 공백만 정리하고 원본 지역명대로 묶습니다. 짧은 동 이름을 전체 주소로 추측하거나 검색 기준 지역으로 채우지 않으며, 같은 동 이름이 다른 시·구를 뜻할 수 있음을 안내합니다. 지역별 가격·거리 통계가 없을 때 AI가 지역별 저렴함이나 가까운 거래 여부를 추정하지 않도록 지시합니다.

`UsedRegionAnalysisTest`와 가격 제외 전 집계를 확인하는 테스트를 추가했습니다. 실행·빌드·테스트와 외부 API 호출은 수행하지 않았습니다. API·AI 재시작 및 프론트엔드 갱신 후 확인합니다.
## 첨부 구매 분석 문서 적용: 상세 전용

사용자 제공 분석 문서 전체를 `backend/ai/app/prompts/used_detail.txt`에 보관하고 **상세 비서 전용 시스템 지침**으로 적용했습니다. 검색 목록 모드의 가격 분포·지역 집계 지침은 별도로 유지합니다. 서버 사실·계산을 우선하는 데이터 계약을 추가했으며, AI가 누락된 매물·가격·상태·링크를 만들지 않도록 했습니다.

상세의 기존 ‘전체 검색 가격대와 비교’는 문서 기준에 맞춰 변경했습니다.

- 제목만 같거나 전체 검색 결과라는 이유로 같은 상품의 비교군에 넣지 않습니다. 현재 구현은 본문에서 명시적으로 구분된 모델/핵심 옵션/상태/구성품/판매 단위/판매 유형을 추출해 같은 값끼리 비교합니다. 자연어의 불명확한 내용은 추측하지 않으므로 실제로 기재된 정보라도 명확히 추출하지 못하면 미확인으로 남을 수 있습니다.
- `모델명: …`, `옵션: …`, `상태: …`, `구성품: …`, `판매 단위: …`, `판매 유형: …`처럼 원문에 확인되는 항목과 짧은 근거 문구를 함께 보관합니다. 이는 판매자 주장이지 실제 성능·진위 확인이 아닙니다.
- 거래 의도와 제시가·협상가·현장 금액 미정·임시 가격·부분 금액·옵션/시작 가격·충돌을 구분합니다. 무료배송이나 부속품 무료 제공을 상품 전체 나눔으로 처리하지 않고, 0원만으로 무료 나눔이라고 확정하지 않습니다.
- 명시된 현재 전체 판매가와 판매 단위가 있어 임시 표시 금액을 해소할 수 있을 때만 본문 금액을 사용하고 원문을 남깁니다. 오타·단위를 임의 보정하지 않습니다. 명확한 해결 근거가 없는 가격 충돌은 보류합니다.
- 검색 후보 최대 1,200개 중 제목 일치 후보를 우선해 최대 60개의 **이미 저장된 상세**를 일괄 읽습니다. 새 외부 매물 검색·자동 상세 수집·14/30/90일 확장·지역 확대는 하지 않습니다. 과거 캐시에 본문·조건이 없으면 통계 적격으로 승격하지 않습니다.
- 선택 매물 자신과 같은 플랫폼 ID의 반복 관측을 비교군에서 제외합니다. 조건·가격·현재 판매 상태·24시간 이내 확인이 맞는 매물만 현재 제시가 통계에 씁니다. 상태 미제공이 많은 중고나라 자료는 판매 중으로 추정하지 않습니다.
- 적격 비교군 5개 미만은 중앙값을 생략합니다. 5~9개나 큰 제약이 있는 자료는 낮은 품질의 참고 중앙값·사분위 범위로만 설명합니다. 10개 이상이면서 조건·판매 상태·최신성·판매자 편중 등에 큰 문제가 없을 때만 같은 상품가 기준 중앙값 차이율을 계산합니다. ‘높음’ 등급은 독립성 등 추가 검증 전 자동 부여하지 않습니다.
- 통계 검토 신호는 비교군 10개 이상에서 로그 가격의 MAD, MAD=0일 때 로그 IQR로 계산합니다. MAD/IQR이 모두 0이면 보정값을 넣지 않습니다. 후보를 비교군에서 빼고 계산하며, 신호만으로 가격을 삭제하지 않습니다. 신호가 있는 가격을 포함한 기본 중앙값과 참고로 제외한 중앙값의 민감도도 가능할 때 제공합니다.
- 원문·사진 주소·지역이 함께 반복되는 경우 중복 의심으로 안내하되 실물 중복 확정으로 합치지 않습니다. 제조사 이미지 하나나 모델·가격만으로 중복을 판단하지 않습니다.
- 공개 판매자 ID가 실제 제공되면 수집기에서 플랫폼별 해시 식별값으로 바꿔 계정 수·편중에 사용합니다. 닉네임으로 판매자를 추정하지 않습니다. 값이 없는 기존 캐시는 미확인으로 남습니다. 해시 식별값은 실제 사람 수·거래 안전 확인이 아닙니다.
- 배송비·필수 수수료가 없으면 총비용을 0원 가정으로 만들지 않습니다. 확인된 최소 비용과 미확정 항목을 구분합니다. 현재 사용자 예산·이동 가능 범위 등 별도 구조화 입력은 없으므로 충족했다고 단정하지 않습니다.
- 가격·조건·비용·판매 상태·6시간 이내 확인과 검토 신호 등의 검토를 통과한 경우에 한해 관측 범위 내 상품가 최저 후보를 제공합니다. 총비용 순위는 동일 거래 방식이며 필수 비용이 확인된 후보끼리 구분합니다. 통과 후보가 없으면 임의 추천을 만들지 않습니다.
- 출처·관측 시각·지역·자료 수·각 제외 사유를 표시하고 대표 근거는 최대 5개로 제한합니다. 통계는 대표 예시만이 아닌 전체 적격 비교군을 사용합니다. 전화번호·계좌·이메일·일부 상세 주소 형식은 분석 전달·표시 단계에서 가립니다.

화면의 ‘구매 분석 근거 보기’는 문서의 7개 순서(판단, 가격/조건, 비교 근거, 가격 차이, 출처, 확인 사항, 한계/시점)를 따릅니다. 답변도 이 순서를 따르도록 지시합니다. 자료가 부족해도 관측된 표시 가격·판매자 설명과 빠진 조건을 먼저 안내하며, 근거가 없는데 비교 수치를 만들지는 않습니다.

수정·추가 테스트: `UsedAgentPolicyTest`, `UsedListingFactsTest`, `UsedRobustStatisticsTest`, `test_used_agent.py`, 수집기의 판매자 ID 해시 처리 사례. 실행·컴파일·빌드·테스트·Firestore 조회·유료 API 호출은 하지 않았습니다. 반영 시 수집기·API·AI를 재시작하고 프론트엔드를 갱신합니다. 기존에 저장된 매물을 새 상세 필드로 보완하려면 사용자가 해당 상세를 갱신해야 합니다.

통계 참고 자료는 첨부 문서에 제시된 NIST Outlier Detection 및 Measures of Scale을 확인했습니다. 로그 변환·표본 수·임계값은 중고 시장의 타당성이 보증된 값이 아닌 초기 정책입니다.
### 제목·본문 자연어 속성 추출

상세 상담은 서버에 저장된 제목(최대 500자)과 본문(최대 4,000자)을 먼저 Gemini로 분석하여 모델, 핵심 옵션, 상태, 구성품, 판매 단위, 판매 유형을 추출한다. 선택 상품을 우선하고 본문이 있는 저장 비교 상세를 포함해 한 번에 최대 6개만 분석한다. 새 상품 수집·외부 검색은 하지 않는다. 검색 목록 상담에는 적용하지 않는다.

각 값에 원문 인용과 제목/본문 출처를 연결한다. Python과 Java 양쪽에서 인용이 실제 원문에 있는지 검증하고, 기존 명시 필드는 유지한다. 문맥상 추정은 ‘문맥 추정 · 확인 필요’로 표시하고 확정 조건 통계나 전체 상품가 판정에는 사용하지 않는다. 원문에 없는 항목은 미확인으로 남기며 미확인 중복 표시는 제거했다.

개인정보를 제거한 공개 텍스트의 해시를 기준으로 추출 결과를 프로세스 메모리에 최대 128개, 24시간 보관한다. 추출 실패는 5분 보관하고 기존 명시 필드로 분석을 이어간다. 캐시가 없는 상세 상담은 추출과 답변 생성 두 단계로 AI를 호출하므로 추가 시간이 걸리고 모델 호출 비용이 늘 수 있다. 두 단계 동안 기존 생성 중 애니메이션을 유지한다. 적용 시 API와 AI 서비스를 모두 재시작한다. 실행·테스트는 사용자 진행 방침에 따라 수행하지 않았다.
### 검색 분석 저장 및 상세 상담 연결

로그인한 AI 구매 비서의 검색 요약 요청(`/search/summary`)에서 가격·지역 집계를 함께 계산하고 Firestore `usedAnalysisCache`에 저장한다. 상세 페이지에서도 같은 요청으로 참고 집계를 표시하고, 상세 상담 응답과 모델 입력의 `assessment.searchAnalysis`에 동일 집계를 포함한다. `detailReport.comparison`은 기존의 동일 조건 비교로 유지한다. 검색 결과를 거치지 않은 상세에는 비교 자료를 만들어 넣지 않는다. 비로그인 검색은 기존 검색 원본 캐시만 저장하며, AI 요약은 로그인 후 생성한다.

분석 키는 검색 원본 ID별 내용 해시, 현재 플랫폼·가격 필터에 해당하는 실제 후보 ID 목록(중복 제거·정렬), 분석 규칙 버전으로 구성한다. 화면 정렬은 키에 영향을 주지 않으며, 같은 원본 문서가 갱신되더라도 내용 해시가 달라져 재계산한다. 원본 ID·버전·후보 목록은 `inputJson`에 보관하고 집계에는 검색어·검색 기준 지역·조회 시각을 함께 연결한다. 원본이 덮어써지면 과거 원본을 복원하는 기능은 제공하지 않는다.

집계 캐시에는 상품 제목·본문과 질문·답변·회원 ID를 복사하지 않는다. 제외 예시에는 플랫폼·상품 ID·가격·사유만 저장한다. 지역 집계의 분모는 가격 제외 전 중복 제거 전체이며, 가격 집계 표본 수와 구분한다. 미제공 지역은 선택한 당근 동네로 채우지 않는다.

유효기간은 최대 24시간이며 참여 검색 원본 중 가장 먼저 만료되는 시각을 넘지 않는다. 만료·미제공 조회 시각의 자료로 캐시 수명을 연장하지 않는다. 서버는 만료 캐시를 읽지 않는다. 물리적 자동 삭제를 위해 Firebase/Google Cloud에서 **컬렉션 그룹 `usedAnalysisCache`, TTL 필드 `retireAt`** 정책을 별도로 활성화해야 한다. 해당 클라우드 설정은 코드 변경만으로 자동 적용되지 않는다. 기존 Firestore 규칙은 브라우저 직접 접근을 차단하고 서버 계정만 접근한다.

AI는 검색 전체 최저·평균·최고·가격 분포와 지역 제공/미제공 집계를 참고로 설명하되 이를 동일 모델 시세·할인율로 대신 사용하지 않는다. 지역별 가격·거리·직거래 가능성은 계산된 자료가 없으므로 추정하지 않는다. 화면에는 상세 상담 상단과 답변 근거에서 접어 볼 수 있는 ‘검색 결과 참고’ 항목을 제공한다.

정렬/중복에 대한 키 안정성, 원본 갱신·후보 변경 시 키 변경, 가장 오래된 원본 기준 만료, 만료 근거의 Firestore 접근 방지, 상세 AI 입력의 검색 집계 분리를 확인하는 테스트를 추가했다. 사용자의 실행·테스트 방침에 따라 테스트와 실제 서비스 호출은 실행하지 않았다.
### 모델명·상품 종류별 검색 가격 형성대

검색 요약의 `productGroups`에 모델별(MODEL) 또는 모델 미식별 상품의 종류별(CATEGORY) 가격 요약을 추가했다. 용량·색상·구성품으로 세분화하지 않는다. 아이폰 15의 128GB/256GB는 같은 그룹이며 프로/프로 맥스 등 모델 변형은 구분한다. 모델 그룹은 동일 상태·옵션 또는 동일 실물을 뜻하지 않는다.

추가 AI 호출 없이 서버 분류 규칙을 사용한다. 주요 제품군의 한글/영문 표기와 모델 변형, 제조사 모델 코드, 본문의 명시 모델명을 먼저 확인하고, 식별하지 못하면 제목의 상품 종류 또는 API categoryName을 사용한다. 호환 케이스·빈 상자 등은 본체 모델로 묶지 않는다. 지원 규칙 밖의 모델은 상품 종류로 분류될 수 있고, 여러 모델이 섞여 있거나 상품 종류도 불명확하면 unclassifiedCount로 남긴다. 모든 제품의 정식 모델을 완전하게 판별하는 기능은 아니다.

그룹마다 조회 수·가격 분석 수·제외 수·최저·평균·최고·중앙값·가장 많은 가격 구간(동률 포함)을 계산한다. 가격은 기존 검색 가격 분석의 유효 양수 가격·판매 상태·명확한 이상 저가 군 제외 기준을 재사용한다. 제목에서 드러난 고장·파손·부품용·구매 희망·대여·예약금·보증금·묶음 판매는 해당 그룹의 정상 가격 참고에서 제외한다. 본문 전체를 검증한 정상 매물 통계가 아니며 미기재 상태를 정상으로 보증하지 않는다. 5건 미만도 관측 가격은 제공하지만 안정적인 가격 형성대로 강조하지 않는다.

현재 필터에 해당하는 검색 후보만 사용하고 provider:productId 중복을 제거한다. 상위 40개 그룹을 표시하며 생략 그룹 수를 알린다. 플랫폼 간 같은 실물의 중복 검증은 수행하지 않는다. 기존 Firestore 검색 분석 캐시의 정책 버전을 올려 이전 캐시와 구분했다.

상세 AI 입력에는 `assessment.searchAnalysis.productGroups`와 `assessment.selectedSearchGroup`을 포함한다. selectedSearchGroup은 선택한 게시글을 제외한 같은 모델명/상품 종류의 전체 검색 참고군으로, 상위 40개 표시 한도와 무관하게 계산한다. 기존 detailReport.comparison의 엄격한 동일 조건 통계와 별도로 제공한다. 질문 제안과 검색 카드·상세 답변의 가격 그룹 표시도 추가했다.

용량 통합/모델 변형 분리, 카테고리 분류, 호환 액세서리 분리, 복수 모델 미분류, 선택 게시글·중복 ID 제외, 잘못된 가격/판매 상태/판매 유형 제외, 모델 코드 별칭에 대한 테스트를 작성했다. 실행·테스트는 사용자 요청에 따라 수행하지 않았다.
### 구매 분석 문서 재적용 — 현재 사이트 정책 유지

첨부된 역할·기본 원칙 문서를 상세 전용 프롬프트 `backend/ai/app/prompts/used_detail.txt`에 반영했다. 검색 상담 프롬프트와 분리하며, 사이트의 명시적 정책(같은 모델명은 용량/색상으로 세분화하지 않고 통합, 모델명 미식별 상품은 CATEGORY 참고 분석)을 최우선 적용 범위로 명시했다. 문서의 옵션 일치·모델 식별 조건은 정밀 비교에 적용하고 검색 참고 자료와 혼동하지 않도록 했다.

답변은 가능한 결론→핵심 근거→비교 범위/비용→중요한 잔여 확인 사항으로 구성한다. 반복 경고·빈 통계 나열·해결된 질문 반복을 피하며 확인 사항은 기본 0~2개로 정리한다. 서버 계산·판정을 AI가 바꾸지 않는다. 제공된 본문에 명확한 값이 있으면 추출 필드가 비었더라도 원문 기재로 설명할 수 있지만, 확정 통계·집계·가격 의미는 수정하지 않는다. 조회 도구가 없으므로 원문 추가 확인·판매자 연락·사진 판독·기간 확대를 수행했다고 주장하지 않는다.

서버는 비용 누락 때문에 적격 상품가 비교까지 보류하지 않도록 판정을 분리했다. 상품가 기준 가격 차이율은 기존 동일 조건/품질 요건을 충족할 때 계산하며, 필수 총비용 미확정은 별도로 남긴다. 추천 최저 후보의 비용·최신성 요건은 유지한다. 확인 질문은 실제 미확인 필드만 나열하고 모든 조건이 확인되면 기본 질문을 억지로 추가하지 않는다. 기존 정밀 비교의 6개 필드 일치 요건 및 추가 수집 범위는 유지한다.

프런트는 상세 답변 밖에 같은 서버 질문 목록을 중복 표시하지 않으며, 전체 목록은 구매 분석 근거에서 확인할 수 있다. 비용 미확정/상품가 비교 분리, 이미 확인된 필드 재질문 방지, 상세 프롬프트 정책 연결 테스트를 갱신했다. 실행·테스트는 사용자 방침에 따라 수행하지 않았다.
### 상세 API 응답 직접 분석 (기존 6개 항목 추출 방식 대체)

현재 프로젝트의 상세 조회 경로는 Reef 응답 → collector의 `listing(..., detail=true)` 정규화 → `UsedClient` 검증 → Firestore 상세 원본 → 상세 상담이다. 이 응답의 실제 필드를 일차 근거로 쓰도록 변경했다. 이번에는 코드의 정규화/응답 계약을 확인했으며 실제 유료 상품 조회·Gemini 호출은 수행하지 않았다. 외부 Reef 문서 URL은 웹 도구로 접근되지 않아 최신 제공자 계약을 검증했다는 의미는 아니다.

`UsedApiEvidence`는 상세 API가 제공한 productId/provider/title/price/status/description/regionName/createdAt/bumpedAt/categoryName/deliveryOptions/sellerName/mannerScore를 허용 목록으로 전달한다. 연락처·계좌·정확한 주소 등은 기존 개인정보 제거 처리를 거친다. sellerKey·임의 원본 속성·사진 URL은 전달하지 않고, 이미지는 개수만 전달한다. 판매자 표시 이름/매너 지표를 안전·동일 판매자 증거로 사용하지 않는다. API 미제공 값은 그대로 미제공으로 두고 대체 값을 만들지 않는다.

`evidence.detailApi`에는 원본 출처·수집/수신 시각·제공 필드/미제공 필드를 연결한다. 이는 필수 여섯 항목 양식이 아니라 전달된 데이터 범위의 설명이다. 별도 Gemini 추출 요청과 5분 빈 결과 캐시를 상세 상담에서 제거했으며 `/internal/used-agent/extract` 엔드포인트도 더 이상 제공하지 않는다. 기존 추출 모듈은 상담 경로에서 사용하지 않는다. AI는 실제 product를 직접 읽고 일반적인 상품 분석 답변을 작성한다.

수집기의 description은 기존 최대 20,000자이며 새 응답에는 descriptionTruncated 여부를 표시한다. 이전 저장 자료에 플래그가 없으면 전체 본문 여부를 확정하지 않는다. 신규 플래그를 받으려면 수집기를 재시작하고 매물 정보를 갱신한다. AI·API 서버도 재시작해야 새 직접 분석 방식이 적용된다.

화면은 6개 필드의 빈 값을 나열하는 대신 상세 API에서 제공한 상품 정보와 AI가 참고한 설명을 보여준다. 서버의 정밀 비교 중간 필드/규칙은 통계 검증용으로 유지하며 API 정보의 제공 여부와 구분한다. 이에 따라 규칙 기반 비교가 성립하지 않아도 제공된 상세 상품 정보와 검색 참고 가격·지역 데이터로 답할 수 있다. 정밀 비교 자체의 조건이나 검증 완료 여부를 AI가 임의 바꾸지는 않는다.

API 데이터 직접 전달·제공 여부/개인정보 제외·빈 비교 필드와 무관한 상세 프롬프트 입력에 대한 테스트를 작성했다. 사용자 방침에 따라 실행·테스트와 실제 API 호출은 수행하지 않았다.
### 최종 판단과 미확인 추가 검토 분리

`UsedPurchaseJudgment`가 상세 API·기존 정밀 비교 결과·선택 상품을 제외한 검색 그룹 자료를 받아 `detailReport.purchaseJudgment`를 만든다. summary/scope는 현재 확보한 근거로 가능한 최종 판단, confirmedEvidence는 실제 판단 근거, reviewRequired는 추가 검토 항목이다. 기존 엄격한 비교 판정은 comparisonJudgment로 보존하며 동일 조건 통계·가격 차이율·추천 최저 후보의 기준은 완화하지 않는다.

동일 조건 비교가 유효하면 그 상품가 결론을 사용한다. 그렇지 않아도 같은 모델/상품 종류 그룹의 유효 검색 가격이 5건 이상이면 중앙 50% 범위와 등록가격을 비교해 검색 참고 가격 위치를 설명한다. 옵션/상태 차이가 포함된 그룹 참고를 정밀 시세·최저가 추천으로 승격하지 않는다. 자료가 적으면 상품명·등록가격·제공된 설명에 기초한 상품 검토로 범위를 제한한다. 비용·현재 판매 상태 등 미확인은 별도로 추가 검토 필요를 안내하며 전체 상품 정보를 무효로 바꾸지 않는다.

가격 충돌/임시·부분 금액/가격 미정, 통계적 가격 차이 신호, 판매완료/예약, 일반 유료 구매가 아닌 거래 유형 등 실제 확인된 문제는 결론에 우선 반영한다. AI는 서버 최종 판단과 근거를 설명하고 미확인만 반복하지 않는다. UI 최종 판단 안에서도 확인된 근거와 미확인 추가 검토 사항을 구분하며 정밀 비교·최저 후보 검토 결과는 별도로 펼쳐 본다.

테스트는 미확인 비용·판매 상태가 있어도 검색 참고 판단이 가능함, 확인된 가격 충돌 판단 보류, 판매 완료의 구매 가능 판정 방지를 포함한다. 사용자 방침에 따라 실행하지 않았다.
### 상품명 주소 오인·null 근거·중복 판정 표시 수정

아이폰16프로 1TB/1테라의 ‘프로 + 숫자’를 도로명 주소로 오인하던 개인정보 정규식을 수정했다. 숫자/영문이 섞인 제품명을 주소로 가리지 않으면서 한글 도로명과 상세주소 라벨 처리는 유지한다. 원본 캐시가 아니라 AI 전달/근거 생성 시 마스킹하므로 새 질문에서는 기존 상세 원본으로 올바른 모델명을 다시 사용할 수 있다. 분류 규칙 변경이 반영되도록 검색 집계 정책 버전도 갱신했다.

JSON null과 문자열 null/undefined/n/a는 확인된 텍스트 근거에서 제외한다. 가격 근거에는 천 단위 구분을 적용하고, 중복 불릿을 제거했다. ‘상품 검토 가능’이라는 모호한 결론은 비교가 불가능한 경우 가격 유리함을 아직 판단할 수 없다는 범위로 명시한다. 기존 엄격한 정밀 비교의 ‘추가 확인 필요’를 또 다른 최종 판단처럼 반복 표시하지 않고 비교 가능 범위로 설명한다. 통계 표본이 없으면 0건·판매자 0%·빈 플랫폼 등 장황한 빈 지표를 나열하지 않는다.

상세 페이지 새로고침 시 메모리 검색 상태가 없어지는 경우에 대비해, 검색 목록에서 매물 선택 시 자료 ID·후보 ID만 sessionStorage에 해당 매물별로 최대 24시간 보관한다. 원본 가격·본문·개인정보는 저장하지 않고 서버가 원본 시각과 자료를 다시 검증한다. 이전 검색 이력이 없는 직접 링크·다른 탭에서는 비교 자료가 없을 수 있으며 임의 복원하지 않는다. 개인정보 정규식 회귀 및 null 근거 방지 테스트를 작성했으며 실행은 하지 않았다.
### 같은 모델·종류 가격 기준 참고용 최종 판단

최종 판단은 가격 의미·판매 상태 등 실제 문제가 없는 경우 같은 모델명/상품 종류의 검색 참고 가격을 우선 사용한다. 5건 이상이면 중앙 50% 구간 대비 낮은 편/대체로 무난한 수준/높은 편으로 설명하고, 1~4건은 관측 최저·최고 범위 대비 위치만 설명하며 적절성을 단정하지 않는다. 자료가 없으면 가격 적절성을 판단하기 어렵다고 밝힌다. 가격 충돌·부분금액·판매완료·통계적 검토 신호 등은 계속 우선 반영한다.

purchaseJudgment.priceReference에 비교 기준·그룹명·표본 수·선택 등록가격·관측 가격 통계를 넣고 화면과 AI 설명에서 사용한다. 모든 최종 판단에 구매 판단의 참고로 활용해 달라는 취지를 포함한다. 용량/상태/구성 차이가 포함된 그룹 가격을 동일 조건 적정 시세나 구매 추천으로 바꾸지 않는다. 낮음/무난/높음 및 소수 상품 종류 표본에 대한 회귀 테스트를 추가했으며 실행하지 않았다.
