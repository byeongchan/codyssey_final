# 저장 완료 후 목표가 알림 평가

구현 코드와 테스트 소스만 작성했다. 설치·서버 실행·빌드·테스트는 수행하지 않았다. 실제 Reef·Gemini 요청이나 외부 푸시는 없다.

## 동작

새 저장 영수증과 `snapshotAlertEvents/{영수증 ID}`를 동일한 Firestore 트랜잭션으로 생성한다. 같은 멱등 키의 재전송은 이벤트를 추가하지 않는다. 이 변경 전에 생성한 영수증에는 이벤트를 소급 생성하지 않는다. 기존 데이터는 수동 알림 평가 또는 별도의 새 멱등 키 저장으로 확인한다.

`CATALOG_SOURCE=snapshot`, `SNAPSHOT_ALERT_EVENTS_ENABLED=true`에서 시작 10초 후부터 5초 간격으로 처리한다. 기본 파일 조회 모드에서는 이벤트 저장은 가능하지만 자동 평가는 대기하며 워커가 Firebase에 접근하지 않는다. 기존 `ALERT_SCHEDULER_ENABLED`와 독립적이다. 환경 변수 변경 후 API를 재시작한다.

한 번에 활성 설정 10개를 조회하고 저장 대상 상품만 평가한다. 매 페이지에서 저장소의 최신 유효 스냅샷 선택을 갱신하고 같은 조회 버전의 가격을 사용한다. 오래된 이벤트도 현재 선택된 가격으로 평가하므로 중간 가격 변동 전체를 재생하는 기능은 아니다. 누락·만료·품절 근거는 알림을 만들지 않는다.

처리 임대는 180초이며 페이지 성공 후에만 커서를 전진한다. 실패 시 60초 뒤 재시도한다. 서버가 종료되면 임대 만료 후 다시 처리한다. 여러 프로세스가 있어도 트랜잭션으로 임대를 획득하며, 중복 실행은 기존 알림 트랜잭션의 관측 시각·조건 전환 검사로 방어한다. 삭제된 설정도 커서 기준점으로 유지할 수 있도록 문서 참조 값으로 페이지를 조회한다. 계정 삭제 중에는 기존 삭제 가드가 개인 데이터 재생성을 막는다.

완료 이벤트는 `status=DONE`이며 `availableAt`이 제거된다. 대기·처리·재시도는 `PENDING`·`PROCESSING`·`RETRYING`이다. 이벤트에는 상품 ID와 내부 처리 상태만 저장한다. 사용자별 알림 내용은 기존 개인 저장소에만 기록하며 공개 수집 응답에 평가 인원·알림 개수를 노출하지 않는다. 완료 이벤트의 7일 보존과 정리는 [보존·정리 안내](SNAPSHOT-RETENTION.md)를 따른다. 미완료 이벤트는 정리하지 않는다.

저장 작업 성공은 저장과 조회 갱신 완료를 뜻한다. 알림 평가 성공까지 기다리지 않는다. 알림은 기존 알림함을 새로 조회해서 확인한다. 별도 팝업·배지 자동 갱신은 아직 없다.

## 실행과 검증 (사용자 직접 수행)

1. `FIREBASE.md`와 `README.md`에 따라 에뮬레이터, Node 수집기, API, 프론트엔드를 각각 실행한다. API 터미널에서 아래 값을 적용한다. Spring은 `.env`를 자동으로 읽지 않으므로 다른 기존 환경 변수도 README대로 설정한다.

```powershell
$env:CATALOG_SOURCE='snapshot'
$env:SNAPSHOT_ALERT_EVENTS_ENABLED='true'
$env:ALERT_SCHEDULER_ENABLED='false'
cd D:\github\codyssey_final\backend\api
mvn spring-boot:run
```

2. 저장 스냅샷이 없는 새 에뮬레이터에서 로그인한다. 소니 목표가 400,000원을 등록한다. 가격 근거가 없으므로 알림은 없어야 한다. 검색 화면에서 소니를 ‘스냅샷 저장’한다. 처리 후 알림함을 새로 열면 현재가 384,900원의 알림이 1개 생겨야 한다. 다른 기능으로 기존 스냅샷을 미리 저장했다면 등록 즉시 알림이 만들어질 수 있다.
3. Emulator UI의 `snapshotAlertEvents`에서 이벤트가 DONE인지 확인한다. 동일 요청 재전송과 새 멱등 키로 같은 가격 재저장 모두 알림을 추가 생성하면 안 된다.
4. 여러 사용자·상품 설정으로 페이지를 넘겨도 저장 대상만 평가하는지 확인한다. 알림 생성 후 페이지 완료 기록 전에 서버를 종료해도 재시작·임대 만료 후 중복 알림 없이 DONE으로 진행해야 한다. 에뮬레이터 데이터는 유지한다.
5. 에뮬레이터 중단으로 실패를 유도한 뒤 복구하고 재시도를 확인한다. ‘알림 평가 성공’으로 잘못 표시하면 안 된다. 파일 조회 모드 또는 워커 비활성화에서는 이벤트가 대기해야 한다.
6. 더 새로운 관측으로 미충족→충족 전환은 `ALERTS.md`의 fixture 변경 절차를 따른다. 이 모드에서는 API와 Node를 모두 재시작한 뒤 각 변경을 저장하고 이벤트 완료를 확인한다. fixture 기준 시각을 함께 증가시켜 역순 관측·미래 관측을 피한다.

테스트 실행 명령:

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
```

저장 트랜잭션 이벤트 생성, 파일 모드 무접근, 대상 상품 필터, 평가 후 체크포인트, 실패 시 커서 유지와 재시도 테스트를 추가했다. 실제 SDK 쿼리·복수 프로세스 경합·중단 복구는 에뮬레이터 검증이 필요하다.
