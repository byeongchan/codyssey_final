# 이메일 인증·비밀번호 찾기·내 정보

## 구현 범위

- 회원가입은 하나의 입력 화면에서 진행합니다. 표시 이름·이메일·비밀번호 입력 → 이메일 입력란의 인증메일 보내기 → 메일 링크 인증 → 같은 폼의 인증 확인 → 회원가입 완료 순서입니다. 계정 생성 시 자동으로 메일을 보내지 않습니다. 발송 실패 시 가입 대기 화면에서 재발송할 수 있습니다. Firebase 기본 인증 메일은 임시 Auth 사용자를 생성한 뒤 발송할 수 있으므로 미인증 계정이 Firebase Users에 표시될 수 있으나, 서비스 회원 기능은 서버에서 차단됩니다.
- 미인증 계정: 동일 가입 폼에서 인증 메일 재발송, 인증 확인, 비밀번호 재설정, 로그아웃·계정 삭제를 제공합니다. 공개 상품 조회는 유지합니다.
- 인증 확인: Firebase 사용자 정보를 다시 읽고 ID 토큰을 강제 갱신합니다. 기존 토큰의 미인증 상태를 그대로 사용하지 않습니다.
- 회원 기능: 프론트엔드 세션은 인증된 사용자만 개인 기능에 전달하고, Spring도 검증된 ID 토큰의 `email_verified`를 검사합니다. 미인증 계정은 개인 API에서 403을 받습니다. 예외는 재인증 후 본인 계정을 삭제하는 경로입니다.
- 비밀번호 찾기: 로그인 화면의 ‘비밀번호를 잊으셨나요?’에서 이메일을 입력하면 Firebase 재설정 메일을 요청합니다. 없는 계정과 요청 성공에 같은 안내를 사용하며 비밀번호나 인증 코드를 자체 서버에 저장하지 않습니다.
- 내 정보: 상단 사람 아이콘 또는 푸터 계정 메뉴에서 이메일·인증 상태·가입일을 확인하고 표시 이름 변경·비밀번호 재설정·로그아웃·탈퇴를 할 수 있습니다. 이메일 주소 변경 기능은 이번 범위에 포함하지 않습니다.
- 재발송 화면에는 메일 요청 후 60초 대기 시간을 적용합니다. 실제 남용 방지는 Firebase의 제한도 따릅니다.

## Firebase Console 확인

1. 해당 프로젝트의 Authentication → Sign-in method에서 Email/Password를 활성화합니다.
2. Authentication → Templates에서 이메일 주소 인증과 비밀번호 재설정 템플릿의 발신자·제목·언어·링크 설정을 확인합니다. SDK 언어는 한국어로 설정했습니다.
3. 이번 구현은 Firebase 기본 메일 액션 페이지를 사용합니다. 커스텀 페이지 주소로 바꿨다면 해당 페이지에서 코드 검증·비밀번호 변경 처리가 구현되어 있어야 합니다.
4. 별도로 복귀 URL을 지정한다면 Authentication의 승인된 도메인에 실제 서비스 도메인을 등록해야 합니다. 개발 환경과 배포 환경의 Firebase 프로젝트가 같은지 확인합니다.
5. Emulator 모드에서는 실제 메일 대신 Auth Emulator가 출력하는 인증·재설정 링크로 확인합니다. 기존 미인증 개발 계정도 인증 절차가 필요합니다.

추가 비밀 키는 필요하지 않습니다. 기존 Firebase 웹 앱 설정과 Spring 서버 자격 증명을 사용합니다. 이메일 발송량·속도 제한과 스팸함도 확인하세요.

## 실행 및 확인

Spring Boot를 재시작하고 프론트엔드를 새로고침합니다. 실행·메일 발송·테스트는 사용자가 진행합니다.

1. 회원가입 탭에서 표시 이름·이메일·비밀번호를 입력합니다. 폼에 계속 머무르는지, ‘인증메일 보내기’를 눌렀을 때만 메일을 받는지 확인합니다. 인증 요청 후 이메일·비밀번호는 고정되며 비밀번호 원문은 화면 상태에서 지웁니다.
2. 인증 전에는 찜·AI 상담을 사용할 수 없고, 공개 상품 조회는 가능한지 확인합니다.
3. 미인증 상태에서는 ‘회원가입 완료’ 버튼이 비활성화되는지 확인합니다. 메일 링크 인증 후 같은 입력 폼에서 ‘인증 확인’ → ‘회원가입 완료’를 누르면 표시 이름이 저장되고 내 정보가 표시되는지 확인합니다. 가입 대기 중 새로고침해도 미인증 계정을 완료 상태로 취급하지 않아야 합니다.
4. 로그아웃 후 로그인 화면에서 비밀번호 찾기를 요청하고, 메일 링크에서 새 비밀번호를 설정해 다시 로그인합니다.
5. 내 정보에서 표시 이름을 수정하고 저장 결과가 반영되는지 확인합니다.
6. 미인증 본인 계정도 재인증 후 탈퇴할 수 있는지 확인합니다. 이 과정은 실제 데이터를 삭제하므로 삭제용 테스트 계정을 사용하세요.

서버 검증 테스트 소스는 `FirebaseSessionVerifierTest.java`에 추가했습니다. 실행하려면:

```powershell
cd E:\github\codyssey_final\backend\api
mvn '-Dtest=FirebaseSessionVerifierTest' test
```
