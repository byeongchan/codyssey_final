# 커뮤니티

홈페이지의 커뮤니티 버튼에서 목록, 상세, 글쓰기와 댓글을 이용합니다. 비로그인 이용자도 읽을 수 있습니다. 작성은 이메일 인증과 내 정보의 표시 이름 등록이 필요합니다.

- 일반 게시글: 회원이 작성하고 댓글을 남길 수 있습니다.
- 공지사항: `serviceAccess/administrators`의 관리자만 작성할 수 있고 서버에서 댓글 작성을 차단합니다.
- 작성자와 관리자는 글·댓글을 삭제할 수 있습니다. 게시글을 직접 삭제하면 제목·본문·작성자 정보를 제거하고 내부 삭제 상태만 보관합니다. 목록·상단 공지에서 제외하고 상세·댓글 조회는 404로 응답하므로 화면에 삭제된 글 자리를 남기지 않습니다. 기존 댓글은 공개하지 않고 새 댓글을 차단합니다. 기존 삭제 표시 글도 동일하게 숨깁니다.
- 작성자 본인만 글·댓글을 수정할 수 있습니다. 관리자는 다른 회원 글의 삭제만 가능하며 내용을 수정할 수 없습니다. 댓글 내용이 실제로 변경되면 `수정됨`을 표시합니다. 게시글에는 수정 표시를 붙이지 않습니다.
- 글은 30초, 댓글은 5초 간격으로 작성할 수 있습니다. 제목 120자, 본문 10,000자, 댓글 1,000자 제한입니다. 새 에디터는 실제 텍스트를 기준으로 10,000자를 제한하고 서식은 별도 구조로 저장합니다. 기존 마크다운 글은 이전 길이 제한을 유지합니다. 임의 HTML은 지원하지 않습니다.
- 목록은 20개, 댓글은 30개 단위로 더 불러옵니다. 전체 탭에서는 삭제되지 않은 최신 공지사항 최대 5개를 상단에 고정합니다. 고정 글은 아래 목록에서 중복 노출하지 않고, 나머지는 공지 여부와 관계없이 최신순으로 표시합니다. 공지사항 탭은 최신순입니다.

## 저장과 설정

서버가 `communityPosts`, `communityComments` 컬렉션을 사용합니다. 브라우저의 Firestore 직접 접근은 기존 규칙대로 차단합니다. 공개 응답에는 표시 이름과 작성자 UID 식별자가 포함되며 이메일은 포함하지 않습니다. UID는 삭제 버튼 표시용 식별자이며 권한 검사는 서버의 인증 토큰으로 별도 수행합니다.

삭제 글 제외 목록·댓글 조회·상단 공지 조회에 추가된 복합 인덱스를 사용하므로 `firebase/`에서 기존 README의 Firestore 인덱스 배포 명령을 실행하고 생성 완료를 확인해야 합니다. 별도 환경변수는 필요하지 않습니다. `OPERATIONS_UIDS`는 커뮤니티 권한과 무관합니다.

탈퇴 절차는 삭제하지 않은 본인 게시글의 제목·본문·작성 시각을 유지하고 작성자 UID를 제거하며 표시 이름을 `탈퇴한 회원`으로 바꿉니다. 본인 댓글은 제거한 뒤 인증 계정을 삭제합니다. 직접 삭제한 글은 탈퇴 후에도 숨김 상태를 유지합니다. 기존 계정 삭제처럼 100개 단위로 진행되며 재요청으로 이어집니다. 다른 회원의 댓글은 원래 글이 삭제된 경우 공개하지 않습니다.

## 확인 절차

1. 비로그인 목록·상세 조회와 로그인 유도 확인.
2. 표시 이름 등록 후 일반 글·댓글 작성, 빈 입력과 길이 제한 확인.
3. 관리자 공지 작성, 일반 회원 공지 작성 거부, 직접 API 호출 시에도 공지 댓글 거부 확인.
4. 타 회원 삭제 거부, 본인 및 관리자 삭제 성공 확인.
5. 게시글 삭제 후 댓글 미노출·신규 댓글 거부, 탈퇴 재시도 후 미삭제 글 내용 유지·작성자 익명화·본인 댓글 제거 확인.
6. 목록·댓글 더 보기, 저장소 장애 시 오류 표시·재시도, 모바일 화면 확인.

## 에디터

글쓰기 툴바의 굵게·기울임·취소선·소제목·목록·번호 목록·인용·코드 블록·링크는 편집 화면에 즉시 적용됩니다. 텍스트를 선택한 뒤 툴바를 누르거나 먼저 서식을 켜고 입력할 수 있습니다. Ctrl/Cmd+B·Ctrl/Cmd+I를 지원하며 별도의 미리보기 전환은 없습니다.

이미지 첨부 버튼과 업로드·조회 API, Firebase Storage 연동을 제거했습니다. 텍스트와 서식만 작성할 수 있으며 이미지 붙여넣기·끌어놓기도 지원하지 않습니다. 커뮤니티에 Storage 버킷 설정이나 요금제 업그레이드는 필요하지 않습니다. 기존 글의 이미지 노드와 첨부 표시는 숨기며 텍스트와 서식은 유지합니다. 기존 파일이나 클라우드 객체를 자동으로 삭제하지 않습니다.

새 본문은 `format=richtext-v1`과 허용된 노드로 구성된 JSON 문자열로 저장합니다. 임의 HTML·이벤트 속성·CSS·스크립트·이미지 노드는 허용하지 않습니다. 서버는 최대 10,000자·2,000개 노드·16단계 중첩·직렬화 길이 100,000자를 검사합니다. 링크는 사용자 정보가 없는 HTTP/HTTPS 주소만 허용합니다. 붙여넣기는 일반 텍스트로 처리합니다.

기존 `plain`과 `markdown-v1` 게시글은 조회할 수 있습니다. 수정 시 기존 내용을 렌더링한 안전한 DOM에서 새 본문 구조로 변환합니다. 텍스트는 React가 이스케이프한 결과만 편집기에 넣으며 서버가 보낸 HTML을 직접 넣지 않습니다.

실행·빌드·테스트는 사용자 수행입니다. 한글 입력·선택 영역 서식·중첩 서식·링크·붙여넣기·본문 길이 제한·기존 글 수정과 이미지 첨부 버튼 제거를 확인합니다.

## 게시글·댓글 수정

게시글 상세에서 본인의 `수정` 버튼을 누르면 제목·본문이 에디터에 채워집니다. 취소하면 서버 원문은 변경하지 않습니다. 게시판 종류는 수정 화면에서 변경하지 않습니다. 공지 수정에는 작성자 본인의 현재 관리자 권한도 필요합니다.

댓글의 `수정` 버튼은 본인 댓글에만 표시합니다. 내용이 같으면 수정 시각을 새로 기록하지 않으며 최초 수정 표시도 생기지 않습니다. 한 번 수정된 댓글의 `수정됨` 표시는 이후에도 유지합니다. 수정 시 작성 시각·작성자와 목록 정렬 기준은 유지합니다.

서버 수정 API는 `PATCH /api/v1/me/community/posts/{id}`(JSON), `PATCH /api/v1/me/community/comments/{id}`(JSON)입니다. 수정 전 버전(`updatedAt` 또는 `editedAt`, 없으면 `createdAt`)을 `version`으로 전달하며 다른 창에서 이미 수정했다면 409로 거부합니다. 삭제되었거나 계정 삭제 중인 자료, 타인 자료는 수정할 수 없습니다. 게시글·댓글 수정 자체에는 새 인덱스가 필요하지 않습니다.

추가 확인: 본인 글·댓글 수정과 취소, 다른 회원 및 관리자의 타인 글 수정 거부, 댓글 동일 내용 저장 시 수정 표시 없음, 실제 변경 후 수정 표시, 작성일·공지 순서 유지, 두 창 수정 충돌 시 덮어쓰기 방지.
