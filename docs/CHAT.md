# 상품별 더미 구매 비서 채팅

상품 상세 오른쪽의 구매 비서 분석 아래에 질문 입력창을 추가했다. 현재 답변은 Spring의 `FixtureChatReply`가 상품·판매처·최근 30일 가격 이력으로 만드는 규칙 기반 예시다. FastAPI·Gemini·Reef로 채팅 요청을 보내지 않는다. 기존 FastAPI 구매 분석은 그대로 별도 동작한다. 실제 모델 연결 시 채팅 생성도 FastAPI 공급자 계층으로 옮겨야 한다.

## 현재 기능과 계약

- 로그인한 사용자만 질문·대화 조회·삭제 가능. 모든 소유자는 서버에서 검증한 Firebase UID로 고정하며 클라이언트의 UID는 사용하지 않는다.
- `GET /api/v1/me/conversations/{productId}` → `{data:{productId,turns:[]},meta}`. 저장된 대화가 없으면 빈 배열. 상품별 한 대화를 사용하며 별도의 대화 생성 요청은 없다.
- `POST /api/v1/me/conversations/{productId}/messages` → 본문 `{"message":"지금 구매해도 될까?","requestId":"클라이언트 UUID"}`. 질문·답변을 한 쌍으로 같은 Firestore 트랜잭션에서 저장하고 전체 대화를 반환한다.
- `DELETE /api/v1/me/conversations/{productId}` → 해당 상품 대화 삭제. 화면은 별도 삭제 확인을 제공한다. 상품당 질문·답변 20쌍을 보관하며, 한도 도달 시 409와 대화 삭제 안내를 반환한다. 한 쌍은 질문·답변·작성 시각·fixture 기준 시각·클라이언트 요청 ID를 포함한다.
- 질문은 공백 제외 비어 있지 않은 1~1000 UTF-16 코드 단위, 요청 ID는 영문·숫자·밑줄·하이픈 16~64자. 서버는 질문 양끝 공백을 제거한다. 잘못된 입력은 400, 존재하지 않는 상품에 새 질문은 404다.
- 같은 상품 대화에서 같은 요청 ID와 같은 질문은 기존 결과를 반환하고 저장·응답 생성·한도 차감을 반복하지 않는다. 같은 ID에 다른 질문은 409다. UI는 전송 실패 후 같은 질문을 재전송할 때 요청 ID를 유지한다. 페이지를 떠나거나 대화를 삭제하면 이 재시도 상태는 초기화된다.
- 사용자당 새 질문은 60초 고정 창에 최대 10회. 여러 상품과 API 프로세스가 Firestore 루트의 같은 카운터를 사용한다. 초과 시 429. 현재 공통 오류 헤더의 Retry-After=5는 다음 재시도 안내이며 창 종료를 보장하지 않는다. 대화 삭제는 카운터를 초기화하지 않는다.
- 짧은 후속 질문은 이전 질문 최대 2개만 키워드 문맥으로 사용한다. 입력 문맥은 현재 질문 포함 최대 3000 코드 단위다. 언어 모델처럼 자유롭게 대화하거나 이전 답변의 의미를 해석하는 기능은 없다.

데이터는 `users/{uid}/conversations/{productId}`에 최대 20쌍의 제한된 배열로 저장한다. 중첩 messages 컬렉션은 만들지 않는다. 전체 대화 문서 조회이므로 별도 페이지·복합 인덱스가 필요 없다. 자동 기간 만료는 없으며 사용자 대화 삭제나 계정 삭제로 제거한다. 질문 원문을 보관하므로 민감한 정보를 입력하지 않는다.

계정 삭제는 conversations까지 정리하고 루트의 채팅 카운터도 제거한다. 계정 삭제를 시작하면 채팅 저장 역시 루트 문서 트랜잭션 검사에 의해 409로 차단된다. 일반 대화 삭제는 다른 탭의 진행 중 전송까지 취소하지 않는다. 여러 탭 사용 시 전송을 멈춘 뒤 삭제해야 하며, 늦은 새 전송이 도착하면 대화가 다시 생성될 수 있다.

## 답변 근거

- 가격·구매 시점 질문에는 재고·배송비 확인·무조건 할인·24시간 유효성 기준의 확정 비교가와 최근 30일 범위 평균을 사용한다.
- 현재가 또는 최신 이력 유효성·최소 7일 표본이 부족하면 판단을 보류한다. 유효한 현재가가 있으면 현재가 자체는 표시한다.
- 충분한 근거에서는 기존 더미 분석과 같은 ±2% 평균 대비 규칙을 설명한다. 저장된 분석 작업 결과를 가져오거나 실제 예측하지 않는다.
- 실제 리뷰 수집은 미연결임을 안내하고 상품 상세의 합성 리뷰 예시와 지원 상태로 안내한다. 대화에서 리뷰·평점·미래 최저가를 만들지 않는다. 알림 질문에는 상세의 목표가 설정으로 안내하고 채팅만으로 설정을 변경하지 않는다.
- 모든 답변은 더미/Gemini 호출 없음을 표시한다. 답변별 `referenceTime`은 fixture 기준 시각, `createdAt`은 API 서버 저장 시각이다. 조회한 과거 답변은 최신 가격으로 자동 재분석하지 않는다. 새 질문으로 현재 fixture 설정을 확인한다. `meta.source=firebase-emulator`, `meta.synthetic=true`는 저장 위치와 예시 대화임을 뜻하며 가격의 최신성을 뜻하지 않는다.

## 사용자가 직접 실행·검증

실행·빌드·테스트는 수행하지 않았다. 새로운 의존성이나 환경 변수는 없다. 기존 README의 에뮬레이터 설정을 사용해 Firebase Emulator, FastAPI, Spring Boot, React를 실행한다. 채팅만 확인할 때 FastAPI는 필요 없지만 옆의 구매 분석에는 필요하다.

Spring 터미널 (기존 Firebase 환경 변수 유지):

```powershell
cd D:\github\codyssey_final\backend\api
mvn test
mvn spring-boot:run
```

별도 프론트엔드 터미널:

```powershell
cd D:\github\codyssey_final\frontend
npm run build
npm run dev -- --host 127.0.0.1 --port 5173
```

1. 로그인 없이 소니 상세 → 채팅은 로그인 안내. 개인 채팅 API 직접 요청은 401.
2. A 로그인 → 소니 상세에서 “지금 구매해도 될까?” 전송 → 더미 표시·현재가·평균·근거 기준 시각 확인. 새로고침과 재로그인 후 대화가 유지되어야 한다.
3. 맥북에서 구매 질문 → 짧은 이력으로 판단 보류. “리뷰 알려줘” → 실제 리뷰 미연결 및 상세의 합성 예시 안내. “목표가 알림 설정” → 설정 위치 안내. 채팅만으로 알림이 바뀌지 않아야 한다.
4. A 로그아웃 → B로 같은 상품 조회. A의 질문이 보이지 않고 B의 삭제가 A 대화에 영향을 주지 않아야 한다. 요청의 query/body에 A UID를 추가해도 검증된 B 범위만 사용해야 한다.
5. API 클라이언트에서 같은 요청 ID와 질문을 두 번 전송 → 질문 쌍이 하나만 늘어난다. 같은 ID에 다른 질문 → 409. 빈 질문·1001자·잘못된 ID → 400.
6. 60초 안에 새 ID로 11번 요청 → 11번째 429. 창이 끝나면 다시 전송 가능. 대화 삭제로 한도를 우회할 수 없어야 한다. 분당 한도를 지키며 20쌍 저장 후 21번째는 409. 대화 삭제 확인 후 빈 목록으로 돌아온다.
7. 새 테스트 계정에서 대화를 만들고 계정 삭제 → Auth·개인 하위 컬렉션·채팅 카운터 정리 확인. 삭제 진행 중 새 질문 저장은 409. 계정 삭제 중단·재개 절차는 PERSONAL-DATA.md 참고.
8. 에뮬레이터를 내려 요청 → 오류 표시, 입력을 보존한다. 다시 실행 후 같은 질문 전송으로 중복 저장 여부를 확인한다. 내보내기·가져오기를 사용한 재기동 후 대화 보존도 확인한다.

작성한 단위 테스트는 인증·소유권·입력 제한, 요청 중복과 충돌, 분당/보관 한도, 질문·답변 함께 저장, 삭제 중 쓰기 차단, 더미 답변 근거와 지원하지 않는 리뷰를 확인한다. 실제 에뮬레이터의 동시 요청·저장·삭제 경합은 위 수동 절차로 확인한다.

구현 참고: [Firestore 트랜잭션과 재시도](https://firebase.google.com/docs/firestore/manage-data/transactions), [Java 트랜잭션 콜백](https://docs.cloud.google.com/java/docs/reference/google-cloud-firestore/latest/com.google.cloud.firestore.Transaction.Function). 생성 함수는 외부 호출 없이 계산만 하므로 트랜잭션 재시도 시 외부 API 호출이 반복되지 않는다.
